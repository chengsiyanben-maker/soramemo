# 報告：海外の航空会社の便のデータを自分で集める（データ担当・11/16）

PM の指示（11/16 11時40分、本人「海外のデータも収集したい」）。report-foreign-carriers（PR #101）の続き。
ブランチ data/foreign-collect（main 2ae2e1f から）。下書き PR。本番には入れていない。

## 結論（先に）
- **海外の会社の便は、すでに毎日の全機の記録に入っていた。** reg_legs（機体ごとの便）と airport_tracks_all（空港ごとの上昇・降下の航跡）は、呼び出し符号が「英字3文字＋数字」の機体なら会社を問わず残している。足りなかったのは「1便1回の実績」としての取り出しと、いつもの時刻
- そこで、**外への問い合わせを1回も増やさずに**（adsb.lol・adsb.im とも0回）、毎日の記録から海外の会社の便の実績を取り出して残す表と、「いつもの時刻」と、その日のずれ（推定）を返す関数を作った（移行 171・テスト t110）
- 乗る便に選んだ海外の便の見張り（案A：門限ギリギリ・ダイバート・引き返し）は、この記録の上に作る次の仕事。通知の決まりと表の持ち方を決めてもらう必要があるので、今回は作っていない（下の 5）

## 1. 今の記録に入っている範囲・入っていない範囲（コードを読んだ結果）
| | 入っている | 入っていない |
|---|---|---|
| 場所 | adsb.lol に問い合わせる4つの円（東：関東〜関西・仙台、西：九州・四国・広島、北：新千歳から250海里、南：那覇から250海里）。日本の主な空港はほぼ全部 | 円の外（海外の空港。海外の会社の便の向こう側の空港は分からない） |
| 機体 | 呼び出し符号が「英字3文字＋数字」の便（海外の会社・貨物・軍の輸送機も） | 登録記号を呼び出し符号にしている機体（自家用機など）。adsb.lol に登録記号のない機体は reg_legs に入らない（航跡には入る） |
| 時刻 | 15,000ft 未満の点を1分に1回（track_points、36時間で消える）→ 毎晩 rwy-learn が空港ごとの航跡にして残す（airport_tracks_all・400日は表、そのあとファイル置き場） | 受信機の届かない低い所（着陸の直前・離陸の直後）は点がないことがある。だから時刻は数分ずれる「推定」 |
| 出発・到着 | airport_tracks_all の dep_here（その空港を出た・着いた）。jp_runways.json に滑走路のある空港 | 滑走路の表にない空港 |

## 2. 作ったもの（移行 171・テスト t110。表を足すので移行と RLS をセット）
| もの | 中身 | 読み書き |
|---|---|---|
| 表 airline_codes | 呼び出し符号の記号 → 便名の記号（BAW → BA）86行。Edge Functions の flight_watch.ts の PREFIX と同じ中身（テストで一致を確かめる）＋日本貨物航空 NCA。japan で日本の会社を見分ける | 誰でも select（事実の表）。書くのは運営だけ |
| 表 foreign_legs | 海外の会社の便の実績。1行＝日本の空港を出た・着いた1回：日・呼び出し符号・空港・出た／着いた・時刻（推定）・便名・会社・登録記号・機種・相手の空港（両方とも日本のときだけ）・引き返し／ダイバート | 関数からだけ（RLS 有効、anon・authenticated には何も許さない） |
| 表 foreign_usual | いつもの時刻：前の8週から、便・空港・出た／着いた・曜日ごと（3回以上）と曜日を問わない（5回以上）の中央値。ばらつき（四分位の幅）が60分を超える便は作らない。0時をまたぐ便（23:50 と 0:10）も正しく出す | 関数からだけ |
| 関数 foreign_legs_build(日) | その日の airport_tracks_all から、日本の会社・日本の機体（JA）でない便を取り出す。登録記号・機種は reg_legs から。何度流しても同じ。元の判定が直った行だけ入れ替え、ほかの日には触らない | 運営だけ・lock_timeout 5s |
| 関数 foreign_usual_build() | いつもの時刻を全部作り直す（実績から作る値なので入れ替えてよい） | 運営だけ・lock_timeout 5s |
| 関数 foreign_late(便名, 日) | その日の実績と、いつもの時刻とのずれ（late_min、分）。いつもの時刻がない便は実績だけ（ずれは出さない）。日本の会社の便・読めない便名は空。「推定です…定刻や航空会社の発表ではありません」の文つき | 誰でも呼べる |
| 毎日の仕事 | foreign-legs：3時間ごと（rwy-learn の30分あと）に今日と前の日を作る。foreign-usual：毎晩1回（日本時間 3時55分）。どちらも statement_timeout 2min・lock_timeout 5s | |

- 引き返し：同じ空港を出て5時間以内にそこへ着いた。ダイバート：前の8週でその便が4回以上着いていて8割以上が同じ空港なのに、一度も着いたことのない空港に着いた
- 航路と機体の記録なので foreign_legs は消さない。退会で消す本人の記録は入っていない
- 影響：チェックイン（乗る便・運用の海外の便に「いつもより○分遅い（推定）」を出すときに foreign_late を使える。画面はまだ変えていないので、出すなら画面案から）・撮る人（海外の塗装機の記録）。経営は使わない

## 3. 確かめた結果
- t110：34項目すべて OK（PREFIX との一致・海外の会社だけ・便名と登録記号・表にない会社も残す・何度流しても同じ・元が変わった行だけ入れ替え・ほかの日に触らない・引き返し・相手の空港・ダイバート・いつもの時刻（曜日・8週・0時またぎ・ばらつき・少ない便）・ずれ（BA5 で +32分、0時またぎで +22分）・RLS と権限・lock_timeout・毎日の仕事の上限）
- `node tools/migrations.mjs check`：番号の重なりなし
- 速さ（手元の PGlite）：航跡21万6千行（30空港×60日）のうち1日2,400回を作るのに約0.2秒。空港と日の主キーで引くので、表が大きくなってもその日の分だけ読む

## 4. 規約と回数
- **adsb.lol**：問い合わせは増えない（今の記録を使うだけ）。データのライセンスは ODbL 1.0（「use it freely, just keep it open」、adsb.lol の Historical data の頁）。API の回数の上限は「環境の負荷で変わる」「4xx が返るなら使い方が間違っている」「将来は受信機を出している人に API キー」（adsblol/api の README）。ODbL なので、foreign_late の答えと画面には出典「adsb.lol（ODbL）」を必ず添える（関数の note に入れた）。作った表（foreign_legs）を誰かに求められたら同じ ODbL で渡せるようにしておく
- **adsb.im**：今回は使っていない（経路の問い合わせを毎晩するのはやめた）。海外の空港の側が分からないのはこのため。条件はまだ読めていない（前からの持ち越し）
- adsb.lol の作者への連絡：回数が増えないので、今回のぶんでは要らない（11/7 からの問い合わせの返事待ちはそのまま）

## 5. 次にやること（本人に決めてほしいこと）
1. **表の大きさ**：海外の会社の便は1日に約1,000〜1,500回の見込み（成田・関西・羽田の国際線が中心）。1行に索引を合わせて約250バイトなので、**1年で約100〜140MB**。無料のプランの 500MB に対して大きい。本番の数を `docs/pm/foreign-collect-check.sql`（読むだけ・前の日1日）で数えてほしい。多ければ、400日より前を今の cold-archive と同じくファイル置き場に移す（消さない）案を足す
2. **乗る便に選んだ海外の便の見張り（案A）**：この記録の上に作れる。今の通知の仕組みは flight_schedule の行から始まるので、(a) flight_schedule に「推定・定刻なし」の行を入れる か (b) 小さな表 foreign_watch を別に作る かを選んでほしい（どちらも移行と RLS）。出せるのは、飛んでいる間の「いつもより○分遅い（推定）」・成田の門限の10分前より遅い見込み・ダイバート・引き返し。出発前の遅れと欠航は出せない
3. **日本の会社でも ODPT にない会社**（スカイマーク・ピーチ・ジェットスター・ジャパン・ZIPAIR・春秋航空日本など）：今回は「海外の会社」だけにした（日本の会社と JA の機体は入れない）。同じ仕組みで入れられるので、入れるか決めてほしい
4. 画面に「いつもより○分遅い（推定）」を出すなら、デザイン担当の画面案から（チェックイン担当への依頼は画面案のあと）
