### 7. 運用を開いたときの機体の位置（airport-traffic）を速く
返す形（iata・at・source・planes[]・planes[].trail）は変えない。画面の直しは要らない。
1. **少し古い答えは待たせずに返す**：置き場（edge_cache）の答えが 20〜60秒前なら、それをすぐ返し、裏で作り直す（EdgeRuntime.waitUntil。同じ入れ物で同じ空港を2つ同時に作らない）。60秒より古いか無いときだけ、今までどおりその場で作る。答えの `at` で古さは分かる
2. **見ている空港は、記録の処理が置き場を新しくする**：見る人が来ると「見る人のしるし」（edge_cache の `trafficseen:HND`。入れ物ごとに1分に1回まで・裏で書く）を残す。30秒ごとの記録の処理は、しるしが3分以内の空港だけ、作った答えを置き場に入れる。だれも見ていない空港には書かない（前に避けた「書き込みが倍」にならない。しるしで数えるので、記録の処理が自分で延ばし続けることもない）
3. **見る人の呼び出しは線を書かない**：線（traffic_trails）を書くのは記録の処理だけにした（書き込み2回ぶん短くなる）。記録が止まって adsb.lol に聞いたときだけ、今までどおり見る人でも書く。記録の処理は入れ物の記憶を使わず毎回作るので、線の更新は抜けない
4. **返す量を減らす**：線は画面が使う着陸・離陸の機体（phase arr・dep）だけに付け、ほかは空の配列。位置は小数5けた（約1m）。画面・now.html・サーバーの運用の判定（ops_core）が線を使うのは arr・dep だけなのを確かめた
- Server-Timing に `shared-stale`（古い答えを返した）・`shared-miss`（作った）が出る。記録の処理の返り値に `shared`（置き場に入れた空港の数）
- ほかの処理を巻き込まないこと：裏の作り直しは見る人の呼び出しの後ろで1本だけ。記録の処理で増えるのは、置き場の読み1回と、見ている空港の数だけの書き込み
