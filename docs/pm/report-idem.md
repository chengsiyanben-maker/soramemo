## 作ったもの

- **移行200**（main の198・#230 の199 の次）：`checkins`・`flights`・`manual_flights`・`intl_flights` に `client_id uuid`（null 可）と一意の索引 `(user_id, client_id)`。null どうしはぶつからないので、ID を付けない今の送り方・前からの行はそのまま。索引は条件なし（画面の upsert の on conflict で使えるように）
- **RLS と権限は前のまま**（もう一度はっきり書いた）：checkins・flights は利用者から書けない。記録帳・国際線は本人が足せて、client_id は insert のときだけ入れられる（update の列の許可には入れていない）
- **関数 checkin**：本文の `cid`（UUID の形のときだけ使う）を受け取り、
  - 前の印を読むのと同時に「同じ人・同じ ID の印」を読む（読み1回ぶん並べるだけで、待ち時間はほぼ増えない）
  - あれば判定をやり直さず `{ ok: true, again: true, ...1回目の印・その印でできた便 }` を返す。初めての演出（first_airport）とボーナスは出さない
  - 新しい印・便には client_id を書く。ほぼ同時に2回届いて索引にぶつかったら、先に書かれた方を返す
  - 止まっている・回数制限の判断の順番は前と同じ。ID がなければ前とまったく同じ動き
- 影響：**チェックイン**（下の依頼）。経営は関係しない。航路と機体の記録は消さない（列を足すだけ）

## チェックイン担当への依頼（画面の送る所）

1. 印を押したとき（ckOptimistic／checkinServerWait の前）に ID を1つ作る：`crypto.randomUUID()`（v7 を作る小さな関数でもよい）。保留に積む `p` に `cid` として持たせる
2. `sendCheckin` の本文に `cid: p.cid` を足す。保留から送り直すとき（flushQueue）も**同じ cid** を使う（作り直さない）
3. 返事が `again: true` のときは成功として扱う（ハンコを取り消さない・初めての演出は出さない・「送れました」の扱い）
4. 記録帳・国際線の記録を足す所（manual_flights・intl_flights の insert）を `upsert(row, { onConflict: "user_id,client_id", ignoreDuplicates: true })` にし、行に `client_id` を付ける（ボタンを押したときに1回作る。送り直しで同じ ID）
5. 関数 checkin の新しいものを先に出すこと（古い関数は cid を無視するだけなので、画面が先でも壊れない）
