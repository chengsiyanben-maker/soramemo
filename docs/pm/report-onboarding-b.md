# 報告：はじめての流れとログイン案B（checkin/onboarding-b）

PM の指示 11/26 13時45分の ④（本人「B」・画面案 design/onboarding #237）。③ stamp-card-b は PM の答え待ちなので、帳面の決まりどおり ④ を先に作った。**ログインと個人情報にかかわるので、出す前に PM が本人に見せる。** 本番の Supabase には何も当てていない（表は変えていない）。

## 作ったもの
- **はじめて開いたとき**（ログインの画面ではなく）O1〜O5 の流れ。今までの3枚の案内は、マイページの「使い方」からだけ開く
  - O1 導入「日本の空港を、旅の記録に。」・はじめる／「もう使っている人は ログイン・デモで試す」（今のログインはそのまま：6けたのコード・同意）
  - O2 使い方（撮る・修行・気軽・あとで決める）。構成は変えない（11/8 の決まりどおり全部乗せのまま。登録のときに答えを保存）
  - O3 行ったことがある空港（メモ）：よく選ばれる9空港＋地方ごとに開く。数がその場で増える。0件は「これから最初の1空港へ」「まだない・次へ」
  - O4 次の予定（出発・到着・日付）／予定がなければ、いちばん身近な空港を1つ（「いまの空港」のはじめの空港にする）
  - O5 できた記録（メモの数・あと○日・最初の小目標）と位置の説明 →「次へ（位置の許可を聞きます）」／「あとで設定する」
  - 段は「1 / 4」の帯と「あとで」（その段を飛ばす）。375×667 でも「次へ」は下に固定で、送らずに押せる
- **ログインしていない人のホーム（O6）**：半券はログインした人と同じ形（範囲の中なら「右へ引いて印をもらう」）。数字の帯の代わりに紺のカード「いま空港にいなくても試せます」（羽田のいまを見てみる・デモで試す・× で閉じると今までの「ログイン／デモで試す」の行）。次のフライト（HND → CTS・あと14日）のカード（シートを引き上げると見える）
- **b1：はじめての印のときに登録**：範囲の中で半券を切ると下からシート「印を残すために、記録をバックアップします」。**「メールで登録しないと、○○の印は押されません」**と書く。メール →「確認コードを送る」→ 今の登録の流れ（コード → 表示名 → 同意）。O2 で答えた人はアンケートを、O5 で許可を聞いた人は位置の説明を飛ばす（段の帯もその分減る）。終えたら15分以内なら位置を測り直して、その印を押す（サーバーで判定し直す）。「いまはやめる（印は押されません）」と、登録の途中で閉じたときは「印は押されていません」と出す。範囲の外では b1 は出さず、ログインした人と同じ理由の文
- **図鑑**：メモの空港（印がまだの所）は淡いピンの枠に「メモ」。マイページに「行ったことがある空港（メモ）」の行（O3 だけを開いて直す）
- メモ・予定・答えはこの端末だけ（localStorage soramemo.ob）。サーバーには送らない

src/index.html で変えた関数：maybeGuide（作り直し）・obDone（続けてログインの画面を出さない）・authRender（flow "onb" を描く）・auTop（飛ばした段を数えない）・authAfterLoad（ログインしたままの人には流れを出さない）・auVerify・auFinish・ログインの画面のクリックの受け手（name-next・survey・agree・exists-go）・homeState（ログインしていない人も同じ半券の形）・checkinServer（ログインしていない人は b1）・zkTile（メモ）。
