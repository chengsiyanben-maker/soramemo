## 1. 作ったもの：移行 160 airport_facts
| 列 | 中身 |
|---|---|
| airport_id | airports の番号（主キー。空港の行が消えたら一緒に消える） |
| opened_year | 沿革のうち、空港として「供用開始」した最初の年（西暦）。滑走路やターミナルだけの供用開始は数えない |
| runways | 今の滑走路の配列 `[{name, length_m, width_m, note?}]`。name は A・B など、1本だけの空港は null。福岡の C・D（35m×30m）は奈多地区のヘリポートなので note に書いた |
| source / source_ref | 'mlit_airport_list' ／ PDF の URL と基準日（例：`https://www.mlit.go.jp/koku/content/002021263.pdf（令和8年9月1日現在）`） |
| updated_at | 直すと今に（トリガー） |

- RLS：誰でも select（図鑑はログイン前のデモでも見る）。insert・update・delete の権限は anon・authenticated に渡さない（書くのは service_role だけ）
- 決まり：年は1900〜2100、滑走路は配列で8本まで、長さ・幅は数（長さ1〜6000m・幅1〜100m）、出典は国交省の一覧だけ
- 行は **82空港**（国の一覧に載っていて番外編でないもの）。行を作らないのは、会社管理の4空港（成田・中部・関西・伊丹）・千歳（共用空港。国の一覧にない）・番外編
- 影響：**チェックイン（図鑑の1空港のデータ欄）だけ**。経営は使わない。airports は変えない
- 移行はもう一度流しても同じになる（on conflict で上書き）

## 2. 中身の決め方
- 出典：国土交通省「空港一覧」（https://www.mlit.go.jp/koku/15_bf_000310.html）の PDF 5つ（国管理・特定地方管理・地方管理・その他・共用。令和8年9月1日現在）。利用ルールは公共データ利用規約（第1.0版、CC BY 4.0 互換）。和暦を西暦に直し数に直したので「加工」にあたる → 画面に「出典：国土交通省『空港一覧』を加工して作成」
- 和暦の直し方：昭和n年＝1925＋n、平成n年＝1988＋n、令和n年＝2018＋n。年のない沿革の行（波照間・岩国など）は前の行の年の続きとして読んだ
- 「旧◯◯空港 供用開始」（広島・鹿児島・石垣など）、「非公共用として」「公共用として」の供用開始（徳之島・宮古など）も最初の供用開始として数えた。**今の場所・今の形になった年とは限らない**（11/9 に書いたとおり、名古屋 2005＝県営になった年）。画面は「開港」でなく「供用開始」と書く決定なので、それに合う
- 年が null の3空港：
  - **羽田**：沿革の最初は「昭和6年 東京飛行場が立川から移転」で、「供用開始」は滑走路とターミナルのものだけ
  - **三沢・岩国**：共用の飛行場で、沿革は民航ターミナルの完成だけ

## 5. チェックイン担当への依頼（帳面にも書いた）
- 図鑑の1空港のデータ欄は `airport_facts` を select して出す（82行なので一度に読んで手元に持ってよい。airport_id で airports とつなぐ）
- 年は「供用開始 1988年」のように **「供用開始」** と書く（「開港」とは書かない）。opened_year が null か、行がない空港は年の欄を出さない
- 滑走路は「A 3,000m×60m」の形。name が null なら記号なし。note があれば添える（福岡の C・D は「奈多地区（ヘリポート）」）
- データ欄の下に **「出典：国土交通省『空港一覧』を加工して作成」**（source_ref の URL へのリンクにしてよい）
- 行がない空港（成田・中部・関西・伊丹・千歳・番外編）は、年と滑走路の欄ごと出さない
