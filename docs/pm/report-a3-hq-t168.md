## 作ったもの
- main（#201・#204 まで）を checkin/a3-hq に取り込んだ（ぶつかりなし。main の src は #203 の土台から変わっていないので web/ はそのまま）
- **原因はテストの側**：t168 の `view()` は視点を変えたあと 1.2 秒待つだけだった。アプリの a3Loop は1コマの中で「機体の距離を測る（a3Sync）→ カメラを動かす（a3Camera）」の順なので、視点を変えて最初のコマまでは、前の視点（全体＝約10km 先の上空）の距離のまま。遅い手元では 1.2 秒で1コマも描けず、「管制塔から 1.6km 以内の機体が0機」＝ `{}` になっていた
  - 確かめ：視点を変えて1コマも描かずに読むと、近い機体は0機・いちばん近いもので 10,471m（PM の `{}` と同じ形）。1コマ描くと 12機・いちばん近いもので 436m（g3）
  - アプリの不具合ではない：画面ではすぐ次のコマ（約30ms 後）で正しい距離になり、細かい形に切り替わる。人の目では分からない1コマの遅れ
- tests/e2e/t168.py：`frames()` を足し、`view()` は 1.2 秒に加えて「描いたコマを2回」待つ（上限 180 秒）。0機のときは、カメラの位置と近い順の4機を出すようにした（次に落ちたとき原因が分かるように）
- tests/e2e/run_all.py：1本の上限を表にし、t168 だけ 1,800 秒（ほかは今までどおり 240 秒）。上限を超えたら run_all ごと止まらず「失敗」として次へ進む
