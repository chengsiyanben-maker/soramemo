## 4. 3D がページを道連れにしない → 不合格（実機は確かめられない）
良い所（コードと Chromium で確かめた）：
- 空港ページを開いただけでは three.js も 3d/hnd.json も読まない○（通信0件）
- 閉じると requestAnimationFrame と20秒ごとの読み込みを止め、renderer を dispose して文脈も捨てる。閉じたあと25秒、airport-traffic の通信0件○
- three.js が読めないときは a3Fail で知らせる○。電池20%以下・弱い端末は自動で軽くする（a3LowBattery・a3Weak）○

足りない所：
- **裏に回したときに止める作りがない**：index.html の visibilitychange は3D を見ていない。ページを hidden にしても20秒ごとの機体の読み込みが続いた（45秒で2回）。描く動き（rAF）はブラウザが止めるが、通信と setInterval は残る
- **WebGL の文脈が失われたときの受け手がない**（webglcontextlost は0件）。文脈を失わせると、3D の所が空の色一色になり、上の「位置を受信中」と下の機体の一覧はそのまま。「表示が止まりました・もう一度」もない（4-3d-context-lost.png）。Chromium は文脈が戻ると描き直したが、iPhone の Safari は別アプリから戻ったときに戻らないことがある＝条件の「真っ黒で固まる」に当たるおそれ
- ほか（案の外）：開いた直後、到着の BAW7 が「05（D）へ」と離陸用の滑走路で出て、数秒後に「34L（A）へ」に変わった（a3Rwy の向きの合わせ方）
- 直し方：3D を開いている間は visibilitychange で hidden なら a3Poll の setInterval を止め、戻ったら1回読んでから再開。canvas に webglcontextlost（preventDefault）と webglcontextrestored を付け、失ったら「3D を開き直す」のボタンを出し、押したら closeAp3d(true)→openAp3d()。iPhone の実機で「3D を開く→ホームに戻る→1分後に戻る」を確かめる

## 6. 外部データが止まっても真っ白にしない → 不合格
- **airport-now（天気・予報・滑走路・便）を 500／時間切れ／空**にすると、どれも「空港の今」の見出しごと消える（renderNow の `if(!d.weather && !d.flights && !d.taf){ box.hidden = true }`）。3D の絵の入口・滑走路・到着と出発も一緒に消え、「読み込めませんでした」も前の値も出ない。時間切れのときは約25秒「読み込み中…」のあと消える
- **flight_alerts を止める**と遅れの欄が消える。遅れがないとき（欄を出さない）と見分けられない
- **airport-traffic を止める**と、滑走路は「推定」に戻るだけで崩れない○
- **電波なし**：開いたあと通信を切って開き直すと、空港ページは前の値が出た（ブラウザの手元の控え）。ただし切ったまま読み直すと「空港の今」は消える。運用の一覧は滑走路・地図に前の値と「電波がありません・最後に読んだ 6時53分」が出る○が、**案内板・特別塗装機・遅れ・短冊・1日の山・定時の6枚が「—」の並び**（6-offline-ops.png）。条件の「『--』の羅列が0」に当たる
- **古い気象通報を今の天気として出す**：秋田（8a-akita.png）と丘珠は前の晩の「21:00 観測」を出し、見出しは「06:55 更新」。秋田は予報（TAF）が「雨・一時 雷」なのに天気は「晴れ」。羽田でも夜中に気象通報が止まれば同じになる
- 直し方：airport-now の最後の答えを空港ごとに端末に残し（運用の ohLastSave と同じ形）、失敗したら前の値に「○時○分の情報・読み込めませんでした（もう一度）」を出す。遅れは「読み込めませんでした」と「いまはありません」を分ける。運用の一覧の各カードも前の数を「約○分前」で出す（地図のカードはもうしている）。気象通報は観測から2時間（目安）より古ければ「○時間前の観測」と出し、運用の推定に使わない【データ担当：airport-now で観測の古さ（age_min）を返すと画面がそろえやすい】

## 7. 375幅・屋外・片手 → 不合格
- **「もっと見る」が縦書き**：到着・出発の下の出典の横の「もっと見る」が 30×110px で1字ずつ縦に並ぶ（375・390 とも）（7-more-vertical.png）。.nowfoot の左の出典が幅を取り切っている
- **字の切れ**：秋田の風「変わりやすい」が枠で切れて「変わりやす」（8a-akita.png）。便の行の「シンガポールから」「上海（浦東）から」が375で2行になり「ら」だけ次の行
- **× が中身にかぶる**：空港ページの × は sticky で、送っても右上（x=308・44px）に残り、遅れのカードの右上・「航空会社・02:50」の行に重なる
- **小さい字**：ターミナルの「まだ」11px、特別塗装機の「この3時間」11px・出典11.5px、押した回数の単位12px
- **押せる大きさ**：「ピン止め」96×36、特別塗装機の「いま飛んでいる特別塗装機 0機」の行 303×22
- 良い所：下のタブ帯と3D のシートは env(safe-area-inset-bottom) を取っていてホームバーにかからない。空港ページは浮いたシートで下が空く。色の濃さ 4.5:1 未満は「押すと読み込みます（約0.7MB）」4.27:1 の1つだけ。意図しない読み込み直しはない（読み込みのときに1回高さが変わるだけ。8秒見て送り位置は動かない）

## 8. 羽田だけの決め打ち → 合格
- **成田（8b-narita.png）・松山**（運用の定義あり）：同じ作りで「空港の今・この先の予報・滑走路の今・遅れ」まで出る。成田は風が弱く「向きは判定できず」と正直に出る

### checkin（チェックイン担当）
1. 【大・6】空港ページの「空港の今」：airport-now が失敗・空・時間切れのとき、見出しごと隠さない。空港ごとに最後の答えを端末に残し、前の値に「○時○分の情報・読み込めませんでした（もう一度）」を出す。遅れの欄は「読み込めませんでした」と「いまはありません」を分ける。運用の一覧のカード（案内板・特別塗装機・遅れ・短冊・1日の山・定時）も前の数を「約○分前」で出す（地図のカードと同じ形）。確かめ方：airport-now・flight_alerts・airport_board を 500 にして 375 で開く／電波を切って読み直す
2. 【大・7】空港の今の到着・出発の下の「もっと見る」が 30×110px の縦書き。.nowfoot の出典の幅を詰めるか、「もっと見る」を出典の上に1行で置く（white-space:nowrap）。あわせて天気の枠の「変わりやすい」の切れ（375）と、空港ページの × が送ったあと中身にかぶる所。確かめ方：375・390 で羽田と秋田の空港ページ
3. 【中・4】羽田の3D：visibilitychange で hidden の間は a3Poll の setInterval を止め、戻ったら再開。canvas に webglcontextlost／restored を付け、失ったら「3D を開き直す」を出す。確かめ方：iPhone で3D を開く→ホームに戻る→1分後に戻る
4. 【中・6】気象通報が観測から2時間より古いときは「○時間前の観測」と出し、運用の推定に使わない（秋田・丘珠で前の晩 21:00 の観測が「06:55 更新」の下に出ている）
5. 【小】撮る人の都心ルートの離陸の札「22/16R」を行き先で 16R／22 に分ける。予報の行を時刻順に。ログインしない人の空港ページの「ここでチェックインすると印が付きます」に「ログインすると」を添える

### yosoku（運用予想担当・specialHTML）
1. 【中・3】「羽田に着く・羽田を出る特別塗装機 この3時間」の、飛んでいる機体の行：時刻の欄が「—」で、1行目だけ名前が下の行に落ちる。時刻の代わりに「着陸まで約○分」か「飛行中」を置いて予定の行と同じ形にし、札「着陸に向かっている」に（推定）を付ける。羽田の地上にいる機体は上の箱に「羽田にいます（推定）」で出す。確かめ方：special_now を差し替えて 0機・地上1機・接近2機を 375 で

### design（デザイン担当）
1. 【大・1】羽田の空港ページの一番上に「いまの羽田」の1枚の画面案：滑走路の向き（着陸・離陸の番号）・風と横風の一言・今日の遅れ（平均か件数）・「○分前」。375×667 で送らずに読めること、色だけに頼らないこと。今の「空港の今」（天気・予報・滑走路の図・便）はその下のくわしくに。印のカード・押した回数との上下は案で比べる
