# 報告：空港の3Dの画面案（1版）

ブランチ design/airport-3d・画面案だけ（アプリには入れない。構想段階なので「反映して」まで本番に入れない）。PM の指示 11/11 18時35分（本人「取り入れて」）。

## 作ったもの
docs/design/airport-3d/ に15枚（一覧は index.html、PNG は png/ に 844 と 667）
- 01 今の羽田の空港ページ（main をデモで撮った）
- 02 入口：「空港の今」のカードの中に止まった見本の絵＋「3Dで見る ›」。「3Dは押したときだけ読み込みます（約1.5MB）」と書く／02n 夜
- 03 全体（昼）：上に閉じる・題「羽田 3D／機体の位置は約2分遅れ」・設定、その下に視点のピル（全体／管制塔／機体）、下に「見えている機体 12機」のシート。名札は空の機体だけ
- 04 機体を押したとき：便名・福岡→羽田・機種・登録記号・高さ・次に向かう所。特別塗装機は札と「機体図鑑 ›」、「この機体から見る」／04n 夜
- 05 管制塔の視点／06 選んだ機体のうしろから（夕方）
- 07a 夕方／07b 夜（管制塔・灯り）／07c 夜（全体）／07d 雲の多い日・霧
- 08 読み込み中（0.9／1.5MB・やめる）／08b 電池の少ないときの軽い版（機体は印・灯りなし・10秒ごと・「ふつうに」）／08c 機体の位置が届かないとき（空港の形だけ・最後に届いた時刻）
- 測った値（幅390・844）：13px 未満 0（単位を除く）・44px 未満 0・はみ出し 0・切れ 0
- 絵は make/scene.js（canvas の小さな描き手・外部の読み込みなし）で描いた止まった絵。TinyAirport は見ていない・まねしていない（低いポリゴンの考え方だけ）

## 迷った点
- 空港の形は仮のおおまかな配置（A・C は 337°、B・D は斜め、ターミナル3つと管制塔）。本番の形は外部データ（地図の形・建物）の規約を確かめてから。データ担当の確認が先
- 全体の視点では機体を約3倍に大きく描いた（本当の大きさだと点になる）。画面に「大きく描いています」とは書いていない（書くかは本人に）
- 夜の灯り：滑走路の縁と進入灯は白い点、誘導路は緑、窓は琥珀。夜の画面の「光る色は2色」は画面の部品の決まりとして、3Dの灯りの白は数えなかった
- 「約1.5MB」「10秒ごと」「約2分遅れ」は見本の数字。本番の大きさと遅らせ方は作る担当とデータ担当で決める
- 「空港の今」の出発・到着（この1時間）は見本。今のカードの中身に合わせて入れ替える

## 本人に決めてほしいこと
1. 入口の場所：「空港の今」のカードの中（おすすめ）か、空港ページのいちばん上の印のカードの横か
2. 名札：空の機体だけ（おすすめ）か、地上の機体も出すか
3. 特別塗装機の尾翼を金にするか（おすすめ：昼だけ金・夜は灰）
4. 遅れの時間（見本は約2分）と、受け取る間隔（ふつう数秒・軽い版10秒）
5. 軽い版に自動で切り替えるか（おすすめ：電池20%以下で自動・「ふつうに」で戻せる）
6. 機体を押したときの「次に向かう所」：到着便は滑走路と残り分、出発便は行き先の空港でよいか

| 機種の大きさで共通の形を伸ばす | 管制塔の視点は機種どおりの長さと翼の幅（B777-300 は B787-8 より長い）。カードに「形は共通で、大きさは機種どおり」。全体の視点だけは見えるように大きく描く |

- 測った値（幅390・844）：13px 未満 0・44px 未満 0・はみ出し 0・切れ 0

## 迷った点
- 角の出典と「位置を受信中」「雲が低い日」の札が同じ段に並ぶ。長い札は「出典 ⓘ」に畳むか、札を短くする
- 07e の雲は上から見ると雲の層で地面が隠れる。見えにくければ全体の視点だけ雲を薄くする
- 機体の大きさの数字（B787-9 長さ63m など）は FAA の一覧で照らす前の見本
