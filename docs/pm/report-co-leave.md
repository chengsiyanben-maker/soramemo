# 退会した人がいたときのエアライン経営（経営の担当・2026年11月5日）

ブランチ：`co/leave-handling`（`co-v3` から。main には入れていない。本番の Supabase にも流していない）

## 1. 洗い出し（いまのまま退会すると、残った人はどうなるか）
アカウントを消すと、経営の表はすべて `auth.users` の `on delete cascade` で消える。

| もの | いまの動き | 残った人の損 |
|---|---|---|
| アライアンス（退会した人がリーダー） | `co3_alliances.leader` が cascade → アライアンスごと消え、仲間の登録も全部消える | **大**：仲間を失う・仲間の施設の効き目・アライアンスのランキングと対抗戦が消える。仲間どうしのフリーセールだけが「仲間でない」まま続く（決まりと食い違う） |
| アライアンス（ふつうの仲間） | 仲間の登録が消えるだけ | なし（仲間が1社減る） |
| 出資（退会した人の会社に出していた） | 記録が消える。お金は戻らない | **大**：出したお金がまるごと消える |
| 出資（退会した人から受けていた） | 記録が消える。受けたお金は残り、毎日の受け渡しが止まる | なし（得をする） |
| 共同運航（退会した人が運航会社・ブロック買い取り） | 契約が消える | **中**：今月分を前払いした5日分のうち、残りの日数の分が消える |
| 共同運航（そのほか） | 知らせなしで契約が消える | 小：取り分・+5% がその時点で消える。知らせがない。消える前の時間の稼ぎも締められない |
| ランキング・シーズン・月の表彰 | 退会した人の行が消え、順位が繰り上がる。もらった印・称号は残る | なし |
| 中古機の売り場 | 退会した人の出品が消える。買った機体は買った人のもの（buyer は set null） | なし |
| 友だち・発着枠 | 友だちの登録が消える・枠が空く | なし |

## 2. 決めた扱い（残った人が損をしないように。ゲームの数字は変えていない。満足度の初期値40も触っていない）
アカウントを消す**直前**に、サーバーから `co3_leave_settle(消す人)` を呼ぶ。
0. 相手の会社は、先にそれまでの稼ぎを資金に入れる（共同運航・出資がある状態で締める）
1. **出資**：退会した人の会社に出していた人には「出した額」と「いまの会社の価値 × 割合」の大きいほうを返す（30日の待ちと、相手の資金で止まる決まりは使わない）。退会した人から受けていた出資はそのまま相手のもの。まだ認めていない申し込みは断ったことにする
2. **共同運航**：すべて終わりにして相手に知らせる。退会した人が運航会社で、今月のブロック買い取りを払っていた販売会社には、今日を含む今月の残りの日数のぶんを返す（いまの収益の5日分 × 残りの日数 ÷ 月の日数）
3. **アライアンス**：いままでの「抜ける」と同じ。リーダーなら会社の価値がいちばん高い仲間に引き継ぎ、新しいリーダーに知らせる。ひとりだけなら消える
- 知らせは会社の新聞に出す。**退会した人の会社名は書かない**（消えた人の名前を残さない）
- 何度呼んでもお金は増えない（2回目は何もしない）

## 4. データ担当への依頼文
> 経営の担当から3点お願いします（ブランチ `co/leave-handling` の `20261105000147_co3_leave.sql` が前提です）。
> 1. **アカウント削除で精算を呼ぶ**：`supabase/functions/delete-account/index.ts` で `admin.auth.admin.deleteUser(user.id)` の前に
>    `const { error: e2 } = await admin.rpc("co3_leave_settle", { p_uid: user.id }); if (e2) throw e2;` を入れてください
>    （または `auth.users` の before delete トリガーで呼ぶ。どちらでも可。失敗したら削除を止める形を希望）
> 2. **ニュースの種類を足す**：`co3_news_kind_check` に `'partner'` を足す移行（RLS はいまのまま）。足されるまでは `'event'` で書くので、急ぎではありません
> 3. **ブロック買い取りの払った額を残す**：`co3_codeshares` に `paid_amount bigint` を足す移行（RLS はいまのまま）。いまは払った額が残らないので、返金を「いまの収益」から計算しています。列ができたら `co3_cs_pay_block` で書き、返金はそちらを使うよう経営で直します
> 
> 外部キーの `on delete cascade` は変えなくて大丈夫です（精算のあとに消えるのが正しい）。
