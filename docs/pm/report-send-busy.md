# 報告：コードのメールが送れないときの言い方（チェックイン担当・11/6）

広告担当の依頼 2（docs/pm/report-ads-early-access.md）の仕事。ブランチ `checkin/send-busy`、下書きのプルリクエスト。main と本番には入れていない。

## 作ったもの
- 「いま登録が混み合っています。1時間ほどあとで試してください。」は 11/5 の新規登録（dc0f933）ですでに入っていた。ただ、Supabase の送信の断り方を見分けておらず、次の2つを直した
  1. 同じアドレスへの送り直しが早すぎたとき（Supabase は「after 42 seconds」と返し、これも 429）にも「1時間ほど」と出ていた → 「コードは1分に1回まで送れます。あと42秒待ってください。」と出す
  2. ログインの画面でも「いま登録が混み合っています」と出ていた → ログインのときは「いまコードの送信が混み合っています。1時間ほどあとで試してください。」
- 混み合いの見分け：429、または code が over_email_send_rate_limit・over_request_rate_limit、または文に rate limit / too many
- 変えたファイル：src/index.html（auSendErr と呼ぶところ2か所）、web/index.html・web/sw.js（作り直し）、tests/e2e/fake_sb.js（送れない場合を真似る口 `__otpErr`）、tests/e2e/t115.py（新しいテスト）

## 確かめた結果
- t115（新）：上限・429だけ・code だけ・早すぎ・ほかの失敗の5通り × 新規登録とログイン、送れたときはコードの画面へ。すべて通過。失敗のときは送った時刻を残さず、ボタンはもう一度押せる
- 登録まわりの t114・t8・t80 も通過
- ブラウザのテスト全体：77/86 通過（運営コンソールの4本は手元にないので飛ばした）。落ちたのは t17・t19・t27・t34・t48・t57・t62・t99・t105
  - t27・t48・t57・t99・t105：前から落ちているもの（帳面に記録済み）
  - t17：main のままでも落ちる（新しく見つけた。今回の変更とは別）
  - t19・t34・t62：1本ずつ流し直すと通る（全体で流すと時間で揺れる）
- スマホ幅（390×844）で撮って確かめた（新規登録・ログインの2枚）
