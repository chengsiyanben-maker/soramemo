## 2. 作ったもの

### 移行200（20261126000200_checkin_idem.sql）
- `checkins.client_id uuid` と一意の索引 `checkins_user_client (user_id, client_id)`。null は何件でもよい（今までの印・ID を送らない古い画面）
- `flights` の索引 `flights_arr_checkin (arr_checkin) where arr_checkin is not null`（移行188・一意でない）を、**同じ名前・同じ形の一意の索引に置き換える**（索引が2本に増えない）。本番に同じ arr_checkin の便が2行あると、**移行は止まらずに置き換えだけしない**（行は消さない）。idem-b-check.sql の 1 で反映の前に見られる
- `manual_flights.client_id uuid` と一意の索引 `manual_user_client (user_id, client_id)`
- RLS・権限は前と同じ：checkins・flights は利用者から書けない。manual_flights は本人が足せて、直せるのは fare・seat・airline・price だけ（client_id は直せない）
- 列と索引を足すだけ。航路と機体の記録は消さない。判定（範囲・30分・20秒）は変えない
- 影響：チェックイン（関数 checkin が ID を受け付ける。画面が ID を送るのは下の依頼）。**経営は関係しない**

### 関数 checkin
- 送る中身に `cid`（UUID）を足せる。なければ今までどおり（古い画面もそのまま動く）
- 往復は増やさない：前の印を読むときに client_id も読み、**前の印と同じ ID なら**すぐ1回目と同じ返事（`dup: true`・ボーナスは空＝2回は払わない・first_airport／first_terminal は「この印より前に同じ空港の印がないか」で1回目と同じ値）
- 前の印より古い ID（保留の送り直しのあとに別の印がある場合）は、**判定で断るときだけ**探して、見つかれば成功で返す
- 同じ ID が同時に2回届いたら、2つ目は一意の索引にぶつかる（23505）→ 先に入った印を返す
- ログ `checkin_dup`（where：last・decide・insert。利用者 ID と位置は書かない）
- 一時停止中でも、記録済みの印の送り直しは成功で返す（読むだけ）

## 3. チェックイン担当への依頼（PM から checkin.md に写してほしい）
1. 印：押したとき（`ckOptimistic`／`checkinServerWait` の前）に `crypto.randomUUID()` で ID を1つ作り、`sendCheckin` の body に `cid` で付ける。返事が来ずに保留するとき（`enqueue`）は**同じ ID を保留の行に入れ**、`flushQueue` の送り直しでもその ID を送る。返事の `dup: true` は成功として扱う（印の数・便は1回目のもの）。ID は1回押すごとに新しく作る（同じ ID を別の印に使い回さない）
2. 記録帳の便（`manual_flights` の insert 4か所：手で足す・機体から足す・計画から足す ほか）：フォームを開いたとき（または「追加」を押した最初のとき）に ID を1つ作り、送れたら捨てる。送るのは `sb.from("manual_flights").upsert({ ...今の列, client_id }, { onConflict: "user_id,client_id", ignoreDuplicates: true })`。失敗して押し直すときは同じ ID のまま。一括取り込み（`import_manual_flights`・200件ずつの insert）は今のまま
3. 打ち切りの秒数（Gemini の案は3.5秒）と送り直しの間隔を入れるかはそちらの判断。入れても、サーバーは同じ ID の2回目を成功で返すので二重にはならない
4. 返す形は前と同じ（`dup` が増えるだけ）。データ側（移行200・関数 checkin）は画面の直しより先に入れてよい
