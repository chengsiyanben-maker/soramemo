# 報告：iPhone のアプリだけの画面（design/ios-app 1版・11/19）

チェックイン担当の依頼（11/18・report-ios-app-base.md）から。画面案だけで、アプリのコード（web/・src/・supabase/・ios-app/）は変えていない。一覧は docs/design/ios-app/index.html、写真は png/（844・-667、I1・I3・index は -full）。作り方は make/make_ios.py → make/shoot_ios.py（色・ホーム・タブ帯は design/pin 4版の部品を make/lib/ に写したもの）。

## 作ったもの（13枚＋一覧）
- ① 位置の許可を頼む前の説明：I1（昼）・I1n（夜）・I1b（「次へ」のあと iPhone の確認が出る場所。iOS の画面は描かず、文は Info.plist の理由の文）・I1c（許可しなかったときのホーム。黒いカードの代わりに「位置が使えないので、チェックインできません」＋設定を開く・デモで試す）・I1d（「正確な位置情報」がオフで、誤差が判定範囲より大きいとき）
- ② オフライン：I2（起動したときにつながらない。全画面・「もう一度」1つ）・I2n（夜）・I2b（使っている途中で切れた。シートの頭に帯）・I2c（チェックインを保留したあと。今の文のまま）
- ③ アプリで隠すもの：I3（一覧の表。関数・今の文・アプリの文・済み／これから）・I3w（今の Safari のホームの帯）・I3h（アプリのホーム）・I3m（マイページの設定）
- 測った値：13px 未満 0・44px 未満の押す所 0・横のはみ出し 0・字の切れ 0（844／667）。I3w は帯でシートがあふれる形をわざと見せている。I1 は 667 では説明の3行目がスクロールの下

## 迷った点
- I1 のボタンは「次へ」1つにして、「閉じる」「あとで」を置かなかった。審査では、確認の前の説明に「許可」の字や抜ける道があると断られることがあると考えた（推定。申請の前に App Store の審査ガイドライン 5.1.1 で確かめる）。断る道は次に出る iPhone の確認の「許可しない」
- 出す時は「ログインか『デモで試す』のあと、はじめてホームを開く前に1回だけ」にした。チェックインを初めて押したときにする案もあるが、ホームの地図が最初から位置を使うので先にした
- 位置の説明の文は Info.plist の理由の文と同じことだけを書き、それ以上の約束（送らない等）は書いていない

## 見つけたこと（チェックイン担当へ）
1. **アプリの中で「ホーム画面に追加しませんか」の帯が出る見込み**：renderInstall() は isStandalone() が偽・IS_IOS が真なら出す。アプリ（WKWebView）では navigator.standalone が真にならないので、NATIVE のときは #installBar・#installRow・doInstall を止める
2. 通知の古い文が3か所（11966・12675・14012 行あたり）に残る。pushButtonHTML と同じ「アプリの通知は準備中です。」に
3. 位置・カメラ・保存のエラーの文が「ブラウザの設定で」のまま（4242・4901・4904・7113・9464 行あたり）。I3 の表の文に
4. Info.plist の UISupportedInterfaceOrientations~ipad に横向きが入っている（報告では「iPad も縦だけ」）。iPad で縦だけにするなら UIRequiresFullScreen も要る見込み
5. 「設定を開く」は iPhone の設定のそらメモを開く（UIApplication.openSettingsURLString。Capacitor の部品が要るかも）

## 本人に決めてほしいこと
1. 位置の説明の1枚を出す時（はじめてホームを開く前でよいか）と、ボタンを「次へ」1つにすること
2. 許可しなかったときのホーム（I1c）に「デモで試す」を出すか
3. 起動したときにつながらない画面（I2）は、今は地図・Supabase の部品を電波があるときに読むので要る。部品をアプリの中に入れる次の段のあとは、I2b の帯だけにしてよいか

# 2版（PM の指示 11/19 9時55分・本人「改良を続けよう」）

一覧 docs/design/ios-app/index.html（2版が上、1版は比べる用に下）。作り方 make/make_ios_v2.py → make/shoot_ios.py。改善担当に見てもらう前提。

## 作ったもの（12枚）
1. 位置の説明：I1-v2（昼）・I1n-v2（夜）・I1b-v2（iPhone の確認の場所）。理由は「空港にいるかを確かめて印を押すため・使うのは開いている間だけ・いる場所を送るのは印を押すときだけ（近くの空港の並びはこの iPhone の中で計算）」。src/index.html を見た限り、位置を送るのは checkin の関数（sendCheckin）だけで、文と合う
   - カメラ・マイクの小さい版：I4c-v2（「搭乗券を読み取る」を初めて押したとき）・I4m-v2（「スマホで受信」を初めて押したとき。音声はこの iPhone の中だけで処理し、送らない）。どちらもボタンは「次へ」1つ、閉じる取っ手なし
2. 電波がないとき（画面はアプリの中に全部入っている前提）：I2-v2 ホーム（地図の絵だけ出ない・チェックインは保留して送る）・I5-v2 運用タブ（カードの枠と題は残し、中身の代わりに「読み込めませんでした／電波が戻ると、自動で読み直します／もう一度」。最後に読んだ時刻があれば出す）・I5n-v2（夜。帯は琥珀の線）・I5z-v2 図鑑（自分の記録はそのまま見られる）
3. 位置を許可しなかった人：I1c-v2 ホーム（設定アプリへの道「設定 › アプリ › そらメモ › 位置情報」を字だけで・設定を開く・デモで試す）・I1e-v2（半券を押したときの小さいシート）
4. 隠すもの：I3-v2（隠すものと「代わりに出す1行」の表。そらメモ＋は「アプリの中では、そらメモ＋の申し込みはできません。」、マイクのエラーの文を足した）
- 測った値：13px 未満 0・44px 未満 0・はみ出し 0・字の切れ 0（844／667、24画面）

## 迷った点
- Info.plist の理由の文は今「印を押すときと近くの空港を出すときだけ使い」。2版の文（印を押すときだけ送り）に合わせるなら、チェックイン担当が Info.plist を直す（I1b-v2 の文）
- 電波がないカードの「もう一度」は自動で読み直すのと重なるが、押せる所がないと止まって見えるので残した
- 1版の全画面（I2）は、地図や Supabase の部品がまだ電波のあるときに読む形なので、部品をアプリに入れるまでの形として残した
- 設定アプリへの道は iOS の版で名前が変わることがある（iOS 18 から「アプリ」の段がある）。ボタンで直接開くのが本命

## 本人に決めてほしいこと（2版）
1. 位置の理由の文（「いる場所を送るのは、印を押すときだけ」）でよいか。よければ Info.plist も同じ文に
2. カメラとマイクも、iPhone の確認の前に小さい説明を1枚出すか（出さずに確認だけにもできる）
3. 電波がないカードに「最後に読んだ ○時○分」を出すか（記録を残す仕組みがいる）
4. 許可しなかった人のホームに「デモで試す」を出すか（1版の2と同じ）
