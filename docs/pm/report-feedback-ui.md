# 報告：不具合・意見を送る画面（checkin/feedback-ui）

PM の指示 11/27 11時40分（本人の指示「ユーザーがバグや不具合を報告できるツールを作っておいて」）。画面案は design/gemini-1126 の F1〜F4。データ側は data/feedback（表 `feedback`・関数 `feedback-submit`、PR 前の 673bfa5f）の名前と形に合わせた。**出す前に PM が本人に写真を見せる。** 本番の Supabase には何も当てていない。data/feedback が先に入らないと、本番では送ると「送れませんでした」になる（表と関数がないため）。

## 作ったもの
- **入口**：マイページの目次のいちばん下に「意見を送る（不具合・ほしい機能・空港データの直し）」（F1）。押せなかった理由の札の下（半券の下の札と、ホームの文の下）に小さな「不具合を知らせる」（できたときは出さない・20秒で消える）
- **送る画面**（下から出るシート・F2）：3択（不具合／ほしい機能／空港データの直し）＋本文（2000字まで・数がその場で増える・超えたら送れない）
  - 空港データの直し（F3）：空港（はじめはいま近い空港・「変える」で選び直す）と「どこが違いますか」（名前・読み／滑走路／供用開始／位置・範囲／ほか。本文の頭に【滑走路】のように付く）
  - 送る前に「いっしょに送るもの：アプリの版・端末の種類・開いていた画面・直前のエラー（空港データなら空港）」を中身ごと見せる。「送らないもの：位置・記録・写真・メールアドレス」
- **送ったら**「受け付けました」（F4。画面案の「最近の更新」は、出すデータがまだないので入れていない）
- **送り先**：ログインしていれば `from("feedback").insert({...})`（返す行は読まない。入れる列は kind・body・app_version・screen・device・last_error・airport・session だけ）。していなければ `functions/v1/feedback-submit` へ POST（起動ごとの使い捨ての値 session つき・利用者 ID は送らない）
- **断られたとき**：送りすぎ（54000／429 too_many）→「送れるのは10分に3件までです」、止めている（55000／503 closed）→「いまは受け付けを止めています」。シートは閉じず本文も残す
- **電波がないとき**：端末に保存（soramemo.fbq・5件・7日まで）して「保存しました・つながったら送ります」。つながったら（と、次に開いたとき）送る
- 直前のエラーの種類：画面のエラー（js・promise）・押せなかった文（app_msg）・位置の許可がない（loc_denied）・正確な位置が OFF（loc_precise）。中身の文は送らない（表の決まり ^[a-z_]{1,20}$）
- 端末の種類は ios_web・ios_app・android_web・other_web などの形だけ。開いていた画面は home・book・log・ops・sg・mypage

src/index.html で変えた関数：say（エラーのとき札の下のリンクと直前のエラー）・ckNote（押せなかった札の下のリンク）・ckLocCard（直前のエラー）・reportClientError（直前のエラー）・mpIdxHTML（目次に1行）。
足した：fbOpen・fbRender・fbAuto・fbRow・fbPost・fbSend・fbqGet・fbqPut・fbqFlush・fbNoteErr・fbErrLink・FB・FB_KIND・FB_PART・FB_MAX・FB_ERR_TXT ほか。HTML：#dFb・#fbErrStub・#fbErrMsg。CSS は style の最後の「不具合・意見を送る」。

## 本人に決めてほしいこと
1. 本文の上限：画面案は 400 字だが、表の決まりの 2000 字に合わせた。400 にするか
2. 「最近の更新」（直したものの一覧・「意見から」の札）は出すデータがないので入れていない。作るなら知らせ（notices）に「意見から」の印を足す形をデータ担当と決める
3. ログインしていない人の入口は、押せなかった札の下だけ（マイページはログインの画面になるため）。ホームの「ログイン／デモで試す」の行にも置くか
4. 送ったあとの文「返事はしていませんが、届いたものはすべて読みます」でよいか
