# 報告：経営の画面のテストと見やすさ（11/6 経営ゲーム担当）

## 1. t99・t105 が落ちていた件 → 画面の側を直すのが正しい
- テストを動かす環境の時間帯が UTC だと落ち、日本時間だと通っていた
- 原因は画面のコード。日本時間の日付（例 2026-09-11）を端末の時間帯で月・日に戻していたので、日本より西の時間帯の端末では1日前に出ていた
  - 台風の計画欠航のカード：9月11日 → 9月10日
  - 発着枠の「来月の申し込み（〇月〇日まで）」：10月31日まで → 10月30日まで
- テストの日付を固定しても直らない（ずれるのは「今日」ではなく端末の時間帯）。海外の利用者や時間帯を変えている人には本当に間違った日付が出るので、画面の側を直した
- 新しいテスト t117：日本・UTC・ロサンゼルス・キリティマティの4つの時間帯で、台風の日付と「3月の申し込み（2月28日まで）」を確かめる（うるう年でない2月の月末も見る）。直す前のコードでは4項目落ちる
- 前に出した #19（keiei/fix-t99-t105）と同じ修正をこのブランチに取り込んだ。#19 は閉じてよい

## 2. 経営の画面の下のタブ（路線・機体）の字の濃さ

## 3. ブロック買い取りの返金を paid_amount から計算する
- 新しい移行 supabase/migrations/20261106000153_co3_block_paid_amount.sql（関数だけ。表・RLS・権限は変えない）
  - co3_cs_pay_block：払うときに、払った額を paid_amount に書く（列はデータ担当が 149 で足したもの）
  - co3_leave_settle：退会のときの返金＝払った額 × 月の残りの割合。払った額の記録がない行（前からある行）は、前のとおり「いまの収益 × 5日分 × 月の残り」
- 新しいテスト tests/sql/t93（9項目）：払った額が残る・お金が動く・アプリからは払えない・あとで収益が変わっても払った額から返す・記録がない行は前のとおり・満足度の初期値40のまま
- 経営の画面（アプリ）には返金の計算はない（サーバーの知らせに出るだけ）ので、画面は変えていない
