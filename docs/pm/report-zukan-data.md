## 1. 名前の読みの表 airport_yomi（作った・未反映）

| 列 | 中身 |
|---|---|
| airport_id | public.airports の id（主キー。airports の全行＝86空港・千歳空港(91)・番外編 95 の 182 行） |
| yomi | 正式な名前の読み（例：東京国際空港（羽田）→ とうきょうこくさいくうこう） |
| index_yomi | 索引の50音順と頭の字に使う読み。ふだん呼ぶ名前で「空港・基地・滑空場」は付けない（例：はねだ・いたみ・こまき・おかだま） |
| alt_yomi | 探す欄で当てる別の読み（最大5つ。例：中部→せんとれあ、羽田→とうきょう、小値賀→おじか） |
| source / source_ref | official（公的な一覧の読み。出典が必須）／manual（手で付けた）。**国土交通省の空港一覧にも国土数値情報の空港データにも読みの欄はないので、今は全部 manual** |
| updated_at | 直すとトリガーで今に |

- RLS：誰でも select（図鑑はデモでも見る）。anon・authenticated には書く権限を渡さない。書くのは運営（service_role）だけ
- 決まり：読みはひらがなと長音だけ（カタカナ・漢字・空は断る）、airports が消えたら一緒に消える
- 影響：チェックイン（図鑑の索引・探す欄）だけ。経営は使わない。airports は変えない
- 愛称のうち公式キャラの名前を含むもの（鳥取・米子など）は alt_yomi に入れていない
- アプリでの使い方（チェックイン担当へ）：182行を1回 select して手元に持ち、索引は index_yomi を `localeCompare(…, "ja")` で並べ、探す欄はカタカナをひらがなにしてから yomi の部分一致・index_yomi と alt_yomi の前方一致で当てる

確かめた結果：t99（26項目）通過（airports とアプリの RAW・EXTRA_RAW の全 id に読みがある、「ちとせ」で 6・91・1001、「せんとれあ」で 2、RLS・書けないこと・もう一度流しても同じ）。t01・t48・t87・t89・t90・t97 も通過。番号の重なりなし。SQL のテスト全部（103本、t49 も含む）も通過（全部のテスト：11/9 夜に手元で約35分）。

## 2. 開港の年・滑走路の出典さがし（表はまだ作らない）

| データ | 出典 | 中身 | 利用条件 | 判定 |
|---|---|---|---|---|
| 国の空港一覧（空港管理状況調書から） | 国土交通省「空港一覧」（令和8年9月1日現在）の PDF：国管理・特定地方管理・地方管理（54）・その他・共用（7） | 滑走路ごとの長さ×幅、「沿革」に供用開始と延長の年（和暦）、輸送実績 | 国交省サイトの利用ルールは「公共データ利用規約（第1.0版）」（CC BY 4.0 と互換）。出典を書けば転載・加工してよい。加工したら「〜を加工して作成」と書き、国が作ったように見せない | **よい（いちばんのおすすめ）**。ただし下の注意 |
| 国土数値情報 空港データ（C28） | 国土交通省 国土数値情報 | 滑走路の長さ・幅（本数は数える）、位置・設置者・運用時間。**開港の年はない** | 製品仕様書に利用条件の記載なし。国土数値情報の利用約款（データごとに商用可・不可がある）を読めていない | 保留（滑走路だけなら上で足りる） |
| AIP（SWIM） | 国土交通省 航空局 | 滑走路の物理的な性状（最も正確） | SWIM のサービス説明書が未読（ストアの見直しと同じ） | 保留 |

注意（本人に決めてほしいこと・確かめてほしいこと）
1. 「開港の年」は一覧に1つの欄としてはない。沿革の最初の「供用開始」を開港とみなす決め方でよいか。三沢・岩国など沿革に供用開始がない空港は空欄にする案
   - 追記（11/9 2回目の回）：「その他の空港」の PDF を読んだ。7空港とも滑走路と供用開始が載っているが、**供用開始は「今の形の公共用飛行場になった年」のことがある**（調布は平成13年、名古屋は平成17年＝県営になった年。戦前からある飛行場でも新しい年が出る）。画面では「開港」ではなく「供用開始（国の空港一覧）」と書く案をおすすめする
2. 会社管理の4空港（成田・中部・関西・伊丹）は国の PDF になく、各空港会社のページへのリンクだけ。会社のページは会社の著作物なので、この4つは国の別の資料（空港管理状況調書そのもの等）を探すか、空欄にするか
3. 番外編（自衛隊の飛行場・滑空場・飛行場）は国の空港一覧の外。出すなら別の出典が要る（今回は調べていない）。「ヘリポート・飛行場の一覧」（同じページの PDF）を読んだ：項目は名称・所在地・設置管理者だけで、滑走路も開設年もない（非公共用飛行場はホンダエアポート・竜ヶ崎など3件）。番外編の滑走路・年の公的な出典は、今のところ見つからない → 番外編は出さない（空欄）案
4. 空港一覧のページの見えない所（メタ情報）に「All Rights Reserved」とあるが、サイト全体の利用ルールは「権利表記がない限り PDL1.0」。本文に権利表記はないので PDL1.0 と読んだ。気になるなら航空局に一言確かめる
5. 年は和暦なので西暦に直す（加工にあたる）。画面の出典は「出典：国土交通省『空港一覧』（URL）を加工して作成」の形
6. 出すと決めたら、表は airport_facts（airport_id・opened_year・runways の JSON（長さ・幅）・出典・基準日・source）の形で、移行と RLS をセットで作る。決まるまで画面には出さない（11/9 の決定どおり）

## 3. 見方の帯の設定を新しい3つへ移す案（チェックイン担当が作るとき用）

今の保存（user_view_prefs、fmt 2）：`{}`＝全部乗せのまま、それ以外は `{ base:構成, layout:{ off:{ book:[隠した見方の id] }, order, tabs, aps } }`。図鑑の見方の id は map（地図）・signs（案内標）・tiles（タイル）・chron（年代記）・region（地方）。選んでいる見方（VIEW.book）は端末だけ（localStorage soramemo.view.book）。

おすすめ
- 新しい id は「地方別＝region」「地図＝map」「行った順＝chron」（名前だけ変え、id は今のまま）。こうすると地図と年代記を隠している人は何もしなくてよい
- off.book から tiles・signs・region を外す（地方別はいつも出るので隠せない）。map・chron はそのまま残す
- 選んでいる見方：tiles・signs・region → region、chron → chron、map → map。構成の値（casual の views.book:"tiles"、VIEW_DEF.book）も region に
- 構成 casual の off.book は ["map","chron"] に（今は地図・案内標・年代記・地方を隠してタイルだけ）
- 「これを隠しますか？」の提案（HS の casual「図鑑の見方」）も tiles ではなく region を残す形に
- 移すのはアプリで読むとき（vpApply と端末の LAYOUT を読む所）に直し、次に保存するとき fmt 3 で書く。**サーバーの行を移行で書き換えない**：古いアプリを開いたままの人が fmt 2 の古い id で上書きしても、読むときに毎回直るので壊れない。order.book があれば同じ置き換えをして重なりを消す
- 移行は要らない（表の形は変わらない）。全員が新しいアプリになったあとで、サーバーの行をまとめて直すかは後で決める

数を見るには：docs/pm/zukan-view-prefs-check.sql（読むだけ・1つの表・20秒で止まる）。作り物の5行で、隠している見方ごとの人数・地図だけの人・知らない id が出ることを確かめた。
