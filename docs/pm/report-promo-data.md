# 広報の動画の材料（日本航空の全機の1日）：取り出す SQL と規約の確認

PM の指示（11/26 14時20分）。ブランチ data/promo-sql。表・移行・RLS は変えていない（読むだけの SQL と手元の道具だけ）。

## 1. 作ったもの
- **docs/pm/promo-day.sql**（本人が SQL Editor で流す・読むだけ・一時ファイルなし）。日付は各文の頭の `date '2026-11-25'` を書き換える
  - ① 便の一覧（1便1行）：便名・登録記号・機種・出発／到着空港・定刻・実際の出発／到着の時刻（日本時間）と、その時刻の元（odpt＝航空会社の運航情報・adsb＝機体の位置からの推定）・欠航・ダイバート。flight_history は約400日分あるので、どの日でも取れる。登録記号が便の記録にないときは、全機の記録（reg_legs）から同じ日・同じ番号・同じ区間の機体で埋める
  - ② 航跡の点（1機1分に1点）：便名・登録記号・出発／到着・時刻（日本時間）・緯度・経度・高度（フィート）。出発の20分前〜到着の20分後（実績がなければ定刻）。**生の点（track_points）は36時間で消えるので、今日か前の日だけ**。前の日の分は翌日の11時ごろまでに流す。行が多いときは文の中の「時間で分ける」2行で午前・午後に分ける
  - ③ 古い日の航跡の線（1便1行）：② が間に合わなかった日用。毎晩の記録（flight_tracks）の線で、点ごとの時刻がない
- **docs/pm/promo-expand.py**（手元で使う。Python の標準だけ）：③ の CSV を ② と同じ形の点の CSV にする。出発〜到着の時刻を道のりの割合で割り振る（時刻は推定。列 time_estimated に true）
- 対象は日本航空の便名（JL。J-AIR・日本エアコミューター・北海道エアシステムの JL 便を含む）と日本トランスオーシャン航空などの NU。JL だけにするなら各文の `flight like 'NU%'` の行を消す。共同運航の他社の便名は数えない（実際に飛んだ1便＝1行）

## 2. 確かめた結果
- 模擬のデータベース（移行を全部流したもの・UTC で実行）に、11/23〜27 の JL 300便・NU 20便・ANA 300便／日と、30秒ごとの航跡の点をまいて、3つの文を全部読み禁止で流した
  - ① 320行（JL・NU だけ。ANA は0）・23ms・全部読みなし。登録記号のない便は reg_legs で埋まった
  - ② 29,664行・567ms・全部読みなし。1便96点（1分に1点。同じ分に2点はなし）。欠航の便は出ない
  - ③ 313行・25ms・全部読みなし。記録と同じ書き方（小数4桁の polyline）の線を promo-expand.py で点に戻せた（羽田→伊丹の3点で座標と高度が一致）
- 本番の大きさの見込み：JL＋NU は1日に約1,000便。② は1便約130点で **約13万行**。SQL Editor で一度に保存しにくければ、午前・午後に分ける。どの文も使う日の分だけを主キーと索引（flight_history の主キー・reg_legs_cs・track_points_cs_t・flight_tracks の主キー）で引くので重くない。statement_timeout は 60秒
- 記録は消さない・変えない（select だけ）

## 3. 規約の確認（広告・広報の動画に使ってよいか）
今回は ODPT の規約のページが JavaScript で描かれる作りで、本文を取り出せなかった。下の ODPT の欄は、11/4 に原文を読んだ確認表（Project「外部データの利用規約の確認表（11-04）」）による。

| データ | 動画で使う所 | 使ってよいか | 条件 |
|---|---|---|---|
| ODPT（JAL の時刻表・運航情報。① の定刻と、src が odpt の実際の時刻） | 便名・区間・定刻・実際の出発到着 | **使ってよい（見込み）**。基本ライセンスは営利・非営利とも可（第4条7）、ほかのデータと組み合わせ可（第4条4）。広告を禁じる条文は 11/4 の確認では見つかっていない | 出典・正確さの保証がないこと・問い合わせ先を出す（ガイドライン 3.1）。航空会社が保証・関与しているように見せない。航空会社の不評になる使い方をしない。元データの大部分を戻せる形で出さない（第8条4）＝**CSV は配らない**（動画は可） |
| adsb.lol（② の航跡の点・③ の線・src が adsb の時刻・reg_legs の登録記号） | 機体の動き | **使ってよい**。データは ODbL 1.0。動画は ODbL の「作品（Produced Work）」で、動画そのものを ODbL で出す義務はない。作品を公に使うときは、データベースから得たことと ODbL で使えることを知らせる文を付ける（ODbL 4.3） | 出典の文を動画の中か最後のクレジットに、SNS では説明欄にも。地図が主役の動画なので、画面の隅にも小さく出すのが通例（OSMF の出典のガイドライン 1.5.9）。読める長さだけ出す。作者の頼み「大量のデータを配り直さない」に合わせ、取り出した点の CSV は配らない |
| 地図の背景（動画を作る人が選ぶ） | 背景の地図 | 選んだ地図の条件しだい | 国土地理院のタイルなら「出典：国土地理院」、OpenStreetMap なら「© OpenStreetMap contributors」を足す |

- そらメモの決まりとの合わせ：航空会社名は事実として書いてよい（「日本航空の便の1日」）。**JAL のロゴ・鶴丸・尾翼の絵・公式の写真は使わない**（ロゴは提携後）。「非公式のアプリ」と明記し、「公式」「提携」の言葉は使わない
- ODPT とまぜた点のデータを外に出すと、ODbL（出す義務）と ODPT（出す禁止）がぶつかる。動画だけを出し、データのファイルは出さない

### 動画に入れる文（案）
最後のクレジット（読める長さ・5秒ほど）と SNS の説明欄に：

> 非公式のアプリ「そらメモ」で作成。日本航空とは関係ありません。
> 便の情報：公共交通オープンデータセンター（ODPT）のデータを加工して作成。データの正確さは保証されません。
> 機体の動き：adsb.lol のデータ（Open Database License 1.0 https://opendatacommons.org/licenses/odbl/ ）を加工して作成。航跡は機体の位置の情報からの推定を含みます。
> お問い合わせ：ryoairtrip@gmail.com

画面の隅（動画の間ずっと、小さく）：「データ：ODPT・adsb.lol（ODbL）／非公式」（背景の地図の出典も同じ所に）

### だめ・不明だった場合の代わり
- **案B（ODPT を使わない）**：adsb.lol の記録だけで作る。② の点はもともと adsb.lol なので、便名は呼び出し符号（JAL123 など）、区間は reg_legs の出発・到着（推定）を使えばよい（必要なら SQL を出す）。出典は adsb.lol（ODbL）だけ
- **案C（航跡を使わない）**：時刻表の区間を空港どうしの大圏の線で結び、定刻で動かす（ODPT の時刻表だけ。出典は ODPT）。実際の動きではないので「時刻表から作ったイメージ」と書く

## 4. 本人に決めてほしいこと
1. **ODPT の規約の原文を1回だけ見てほしい**：https://developer.odpt.org/terms/data_basic_license.html の第4条・第8条（今回は本文を取り出せなかった）。広告・宣伝に触れた文があれば教えてほしい。なければ上の表のとおり使ってよい見込み
2. どの日の動画にするか。前の日なら翌日11時ごろまでに ② を流す。それより前の日なら ③ と promo-expand.py（時刻は推定）
3. JL だけか、NU（日本トランスオーシャン航空など）も入れるか（SQL は両方入り）
