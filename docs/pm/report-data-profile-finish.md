# 新規登録のデータの仕上げ（データ担当・2026年11月5日）

ブランチ：`data/signup-profile` に足し、`feat/signup` に取り込んだ。main には入れていない。本番の Supabase にも流していない。`data/profiles` は消していない。

## 取り込んだもの（data/profiles から、user_profiles と agree_terms に合わせて）
- **規約の版の表 `terms_versions`**：`kind`（`terms` 利用規約・`privacy` プライバシーポリシー）・`version`（改定日 YYYY-MM-DD）・`effective_on`（有効になる日）・`url`。user_profiles が規約とプライバシーの2つの版を持つので、1つの表に種類の列を足した
  - いまの版を入れた：利用規約 2026-10-15・プライバシーポリシー 2026-10-21（アプリの `TERMS_VER`・`PRIVACY_VER`、terms.html・privacy.html の改定日と同じ）
  - RLS：だれでも読める。足す・直すのは運営者が移行で（利用者には書く権限なし）
- **いま有効な版 `terms_current()`**：`{"terms": 版, "privacy": 版}` を返す（日本時間の今日までに有効になった最新）。今のアプリは使わない。改定のときに使える
- **agree_terms の版の確認**：呼び方（`agree_terms(規約の版, プライバシーの版)`）は同じ。**表にある版だけ**受け付ける（ない版は `unknown version`）
  - 「いま有効な版だけ」にはしなかった。改定の版を先に足しても、今の定数のままのアプリで同意が止まらないようにするため（画面が今のまま動くことを優先）
- **バックアップ**：`admin_backup` に `user_profiles` を足した（20261021000065_shugyo のものに1行足しただけ）。`tools/restore_from_backup.py` も `user_profiles` を戻せるようにした
  - アカウントを作り直すと空のプロフィールが自動でできるので、**空の行（表示名なし・同意なし・未回答）だけ**バックアップの行で置きかえる。中身のある行は上書きしない

## 取り込まなかったもの（理由）
- `profiles` の表そのもの・`profiles_guard`・`my_signup_at`：user_profiles を正とすると決まっているため（同じ役目はすでに user_profiles にある）
- 規約の版への外部キー：版の種類が2つになったので、表の制約ではなく agree_terms の中で確かめる形にした
- 「運営者が戻すときは日時をそのまま残す」ための見張りの切り替え：代わりに戻しの道具で「空の行を消してから入れる」形にした（user_profiles の見張りはそのまま）
