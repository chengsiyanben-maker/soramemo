## 作ったもの
- tools/build_font.py
  - 取得先を raw.githubusercontent.com/google/fonts/main/... にした。だめなときだけ今までの github.com/google/fonts/raw/main/... に切り替える
  - 一時的な失敗（5xx・429・つながらない・空の返事）は、10秒・30秒と待って1か所3回まで試す。404 などは取り直さず次の取得先へ
  - 一時ファイル（.part）に落としてから置き換えるので、途中で切れた壊れたフォントは残らない
  - 全部だめなら、試した URL と理由を並べて止まる
- .github/workflows/deploy.yml の「アプリ」の段：元のフォント（tools/fonts/*.ttf、約10MB）を actions/cache@v4 で残す。キャッシュの名前は build_font.py の中身から決まるので、取得先やフォントを変えたら作り直される。キャッシュがあれば GitHub から取りに行かない
- tests/tools/test_build_font.py：作り物の 504・404・つながらないで、取り直し・3回まで・切り替え・壊れたファイルを残さないことを確かめるテスト8件

## 確かめた結果
- python3 -m unittest discover -s tests/tools：8件とも成功
- 本物の取得：元のフォントを消してから node tools/build.mjs を流し、3つとも raw.githubusercontent.com から取れて最後まで作れた（明朝体10ファイル 217KB・ドット10ファイル 75KB。今までと同じ）
- deploy.yml：YAML として読み込み、「アプリ」の段に「道具を用意する」→「元のフォントをキャッシュから戻す」→「配る用を作る」の順で入ったことを確かめた。キャッシュが本当に効くかは、main に入れて Actions を2回動かすまでわからない（1回目に保存、2回目から使う）
- 画面は変えていないので、スマホ幅の撮影はなし
