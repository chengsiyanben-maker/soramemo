# 新しい印の位置を小数3桁（約100m）に丸めて残す（データ担当・11/26 本人の OK ③）

ブランチ data/round-pos（main 594dd3e から）。**移行なし・表は変えない**。テストは deno の supabase/tests/pos_test.ts。影響：チェックイン（新しい印の checkins.lat・lon が小数3桁になる。判定・返事は同じ）。経営は関係しない

## 1. 作ったもの
- `supabase/functions/_shared/pos.ts` の `roundPos`：小数3桁に丸める（正負で同じ丸め・数でないものはそのまま）
- 関数 checkin（index.ts）：checkins に書く lat・lon だけを roundPos にした。**判定（decide）は丸める前の値のまま**。accuracy_m・position_at・created_at はそのまま
- 今までの記録は変えない（データベースの中で丸め直す仕組みやトリガーは作らない。バックアップから戻した古い記録も元の値のまま）
- 印を書く所は関数 checkin の1か所だけなのを確かめた（移行・関数の中にほかの書き込みはない）

## 2. 確かめた結果
- pos_test.ts 6本：3桁に丸まる・負の値も同じ・2,000個の乱数で小数は3桁まで、ずれは 0.0005 度まで・ずれは 100m 未満・数でないものはそのまま・**丸めると円の外になる境目の位置でも、丸める前の値で判定して印になる**
- judge_test.ts・idem_test.ts も通過（48本）。deno check（関数 checkin の型）通過。秘密の文字列なし

## 3. 気づいたこと
- checkins の lat・lon を読む SQL の関数はない（管理の取り消しも座標は使わない）。画面で自分の印の位置を出す所があれば 100m 単位になる
- 断った記録（log_rejection）は前から座標を残していない（最寄り空港・距離・誤差の目安だけ）

## 4. 本人に決めてほしいこと
- なし（列も表も変えないので、PM の自動の反映でよいと考える）。関数 checkin を出し直すと効く
