# 報告：電波・位置が悪いときの続き（checkin/stamp-edge）

PM の 11/25 23時の積み（本人が貼った Gemini の案 docs/pm/ext/gemini-offline-1125.txt の 1〜4）。main（4844f048・stamp-fast 入り）から。stamp-fast で入れたもの（押したらすぐ・保留・断られたら取り消し・位置の使い回し）と、位置の取り方は変えていない。

## 作ったもの
1. **何が足りないかのカード**（ckLocCard）
   - iPhone で誤差が 1km 以上（「正確な位置情報」が OFF のときの大まかな位置）：「空港の判定に『正確な位置情報』が必要です」＋道順（設定 › Safari（アプリはそらメモ）› 位置情報 › 正確な位置情報）。サーバーには送らず、ハンコも出さない。ボタンは「閉じる」だけ（アプリは「あとで」「設定を開く」）
   - ウェブで位置の許可がない：「印を押すには、位置の許可が要ります」のカード。ホームは半券の代わりに「位置が使えないので、チェックインできません」のカード（アプリの I1c と同じ形。ボタンは「デモで試す」だけ）。設定から戻って許可されていたら半券に戻す
2. **送信待ちの見せ方**
   - 送れていない印は、読み直しても地図・図鑑・数に残す（qMerge。端末の判定で通る見込みの分だけ。範囲の外などで保留した分は送るまで印にしない）
   - ホームのシートの帯は「送信待ち ○件」＋1件ずつの札「羽田空港 送信待ち（14:22 記録）」。図鑑の詳しい所は押した回数の下に札、押した記録の行に「送信待ち」。札を押すと送り直す。いくつあっても記録した順に送る（今の flushQueue のまま）
3. **確定の札**：保留していた分が送れたら「羽田空港の印が確定しました」（2件以上は「羽田空港など2件の印が確定しました」）。stamp-fast の toast（design/micro の 05 の形・2秒）
4. **文の言い方をそろえた**（CK_TXT・ckWhyText・ckOutText）
   - 届かない：「通信が混み合っているため、いまの記録を端末に保存しました。つながり次第送ります。」（電波がないときは頭を「電波が届かないため、」に）
   - 範囲の外：「いちばん近い羽田空港まであと 2.4 km です。空港に入るとチェックインできます。」（誤差が残りの距離より大きいときは、下のずれの文）
   - ずれ：「建物の中のため、現在地が少しずれているようです。窓の近くか屋外で、もう一度押してください。」（10秒で位置が定まらないときも）
   - 同じ所にもう一度：「本日のチェックインは完了しています。続けて今日の便を記録できます。」
   - 時計のずれ（サーバーの stale_position）：「端末の日時がずれているようです。設定で『自動設定』をオンにしてください。」
   - サーバーの文に英字が入っていたら「サーバーで問題が起きました。少し待ってからもう一度押してください。」に置き換える
   - 入れていないもの：位置が取れていない・範囲の外を「羽田空港として保存する」で通す案

## 本人（PM）に決めてほしいこと
1. 「正確な位置情報」OFF の見分けは「iPhone で誤差 1km 以上」にした（iOS は OFF のとき数km の誤差を返す）。位置の取り方は変えていないので、カードが出るのは10秒待ったあと。早く出す（誤差が数km のまま3秒たったら区切る）なら位置の取り方を変えるので OK がほしい
2. 「本日のチェックインは完了しています」は、今の決まり（同じ所は30分あける）で断ったときに出す。30分すぎれば同じ日でももう一度押せるので「本日」は少しずれる。決まりを「同じ日は1回」に変えるか、文を「さっきチェックインしました」寄りにするか
3. 指示の文のあとに、ずれの文は「窓の近くか屋外で、もう一度押してください。」を1文足した（何をすればよいか分かるように）。要らなければ外す
4. 送信待ちの帯のふちは前からの点線（.queuebar）のまま。デザインの原則（黒い線を使わない）に合わせて薄い影のカードにするなら、ほかの帯（新しい版・ホーム画面に追加）も一緒に変える
