# そらメモ（空港チェックインアプリ）担当の決まり

駅メモの空港版。空港にチェックインして印を集める位置情報アプリと、
実際に飛んだ区間だけで路線を作る「エアライン経営」ゲームの2本立て。
開発は1人。サーバーは Supabase、便の情報は ODPT。URL は https://soramemo.jp/ 。
（リポジトリの main には CLAUDE.md がないので、担当はこのファイルを決まりとして読む。PM が管理する）

## 返答のルール
- 返答はすべて日本語。途中の報告やコミット後の短い返事も含め、英語を混ぜない
- 実装の前に「変えるファイル・手順・確かめ方」を3行で示す
- 構想段階の機能は、本人が「反映して」と言うまでアプリに入れない（main にも本番の Supabase にも入れない）

## 担当の分け方
- 担当は7つ：チェックイン・経営ゲーム・データ・デザイン・改善・広告・受信機（11/6 新設、jushinki.md）。指示は PM から来る
- チェックイン担当の下に3つの担当（11/6 新設）：修行モード（shugyo.md）・撮る人用（satsuei.md）・運用予想（yosoku.md）。持ち場はそれぞれの帳面に書く。下の担当は、ホーム・運用の土台・マイページ・タブ帯・共通の見た目を変えない。変えたいときはチェックイン担当の帳面の「下の担当からの依頼」に書く。チェックイン担当は、下の担当の持ち場を変えるときは先にその帳面に書く
- 下の担当はみな src/index.html を触るので、始める前に main を取り込み、変える関数の名前を報告に書く
- 改善担当は、デザイン担当の画面案を別の目で見て指摘する役。画面案はデザイン担当が直す
- チェックインは経営のコードに、経営はチェックインのコードに触らない
- 表・移行・RLS・外部データの取り込み・毎日の処理はデータ担当だけが触る
- 各担当は自分のブランチで作業し、下書きのプルリクエストと報告（docs/pm/report-*.md）で止まる

## 決定事項（本人が指示するまで変えない）
- エアライン経営の満足度の初期値は 40。ほかの数字を調整するときも動かさない
- 経営の路線は実際に飛んだ区間だけ。車などでの移動も今のまま数える。例外として、貨物の会社は見た貨物機が実際に飛んでいる区間を、乗らずに貨物の路線にできる（旅客は運べない）
- 会社の機体は、乗った機体と見た機体（見た機体は乗った機体と同じ数まで）。不明なら機種で代わりの機体。小型機6機種（セスナ172・アイランダー・キャラバン・PC-12・R44・H125）は見ていなくても買え、登録記号は「SM-」
- 収益はその日の実際の便数・欠航で上下させる
- 課金要素は稼ぎやランキングに効かせない
- 航路と機体の記録は消さずに残す。空の道すじは全機の航跡
- 退会したときは本人の記録（乗った便・チェックイン・経営の会社など）を消し、全機の航跡と機体の記録は残す
- 機体図鑑は特別塗装機だけ
- 空港ページは羽田を先に仕上げ、ほかの空港へ広げる
- 航空会社名は事実の記録としてだけ使う。ロゴや空港の公式キャラは提携後
- バックアップは有料機能にしない
- 新規登録：確認コードは6けた（メールは Gmail、Supabase の送信上限は1時間100通）。表示名は空で始める。使い方のアンケート（撮る・修行・気軽・あとで決める）で最初の構成を決め、その後は使い方から勧める。今いる利用者には次に開いたとき一度だけ同意を求める。「デモで試す」は残す
- プロフィールの表は data/signup-profile（user_profiles）を正とする。data/profiles は使わない
- 運航予想と運用予想は実績と分けて持ち、画面では「予想」と出し、保証しないと書く
- 広告：有料のプロモーションと有料の道具は使わない。投稿は本人が手で、週3回（フィード2・ストーリーズ1）、リールは月2本まで。毎回「非公式アプリ」と明記

## 却下済み（再提案しない）
- 天気の実績、印に付く天気（雨の日の印など）
- 運用（北風運用など）を集める印・バッジ
- 窓側の席ガイド、機体と運航の実績、空のカレンダー
- 今日のお題、季節のスタンプ
- アプリ全体を出発案内板風にする案
- 新造機の製造の進み具合、航空ニュース

## デザインの原則
- モダンなゴシック体に統一
- 数字は大きく太く、単位や補足は小さく薄いグレー
- 大胆な余白。黒い区切り線は使わず、角丸カード＋薄い影
- 本文は真っ黒でなく濃いグレー。JAL赤・ANA青は控えめなアクセント
- ボタンやタブはピル型。地図は航空図風
- ホームは「地図とシート」、マイページは「タイル」
- 出発案内板風は「近い空港のコード（パタパタ）」と「最近の印」だけ
- 画面が絡む変更は、作る前にデザイン案を見せる

## 運営のアカウント
- そらメモの運営はすべて Google アカウント「旅そら」（ryoairtrip@gmail.com）で行う（11/6 本人）。新規登録の確認コードを送る Gmail（Supabase の SMTP）・ストアの開発者登録・外部への問い合わせ（adsb.lol・ODPT・OpenSky・SWIM など）・運営の連絡先は、どれもこのアカウント
- 問い合わせの文を書くときは、差出人をこのアドレスにする前提で書く。パスワードや確認コードはどこにも書かない

## データの扱い
- テーブルを変えるときは、移行（マイグレーション）と RLS を必ずセットで出す
- 外部データ（ODPT、ADS-B など）は利用規約で許される使い方か確認してから使う
- API キーやパスワードをコードに直書きしない
- 担当は本番のデータベースにつなげない。本番の数字が要るときは、本人が SQL Editor で流す読むだけの SQL を書く
