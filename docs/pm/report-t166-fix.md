# 報告：t166 の落ち（checkin/t166-fix）

## 原因（本物の不具合でした）
- 3D の「跳んだ所は少しずつ合わせる」（A3K.smooth・#278 で入った）に、**答えの位置のまま止めて描く地上の機体**にも速さ（走行中の kt）を渡していた
- こまの間が長い（重い端末・裏から戻ったとき・テストを同時に流したとき）と、smooth は「速さどおりに動いていない＝跳んだ」と見なし、描く位置を進む向きへずらしていた。ずれは積み重なり、118 ノットの JL 485 で約 455m 前へ
- 地上の機体の画面の位置がこまごとに揺れるので、t166 で「見えている機体の位置を読んでから押す」間に 40px 以上ずれ、何も選ばれなかった（4本同時で1回再現：sel が None）。PM の見立ての「時刻」ではなく、こまの間の長さによるもの（時刻を3時間おきにずらしても毎回成功）
- 本番でも、重い iPhone で滑走路や誘導路を走る地上の機体が、少し前へ飛んでは戻る動きになっていたはず

## 直したもの
- src/index.html
  - **a3Planes**：機体ごとに `k.mv`（描く位置が時刻とともに動くか）を付けた。前後の答えのあいだ・空の先読み・途切れた着陸機は動く。地上で答えの位置のまま描く機体は動かない
  - **a3Sync**：`k.mv` が false の機体は smooth に速さ 0 で渡す（跳んだ所を合わせる動きそのものは今のまま）
- web/ を組み立て直した
- テスト
  - t166：1.2 秒おきのこまを6回まねて、止まって描く地上の機体が1m もずれないことを確かめる行を足した（直す前の web では 455m で NG になるのを確かめた）。押す機体を選ぶのと押すのを同じ評価の中で行うようにした。視点を変えたあと、新しい視点で2こま描くまで待つようにした（重いとき「管制塔の近い機体 0 機」で1回落ちたため）。「札は重ならない」が落ちたときは札の位置も出すようにした
  - tests/kin/a3kin.test.mjs：止まった答えに速さ 0 ならこまの間が長くても動かない（速さを渡すとずれる）を足した
