# 機体の運用予想を当てる：報告（2026年11月5日）

ブランチ `data/rotation-predict`。本番には何も流していません（「反映して」と言われるまで流さない）。

## 1. 今の仕組み

画面は「この先の便（推定）」ボタン（特別塗装機の一覧と、機体のカード）。`src/index.html` の `loadPrediction` が、次の順に呼びます。

| | `predict_rotation`（JAL・ANA） | `predict_rotation_reg`（全機） |
|---|---|---|
| いまの便 | 今日 flight_watch で登録記号が分かった便のうち最新 | reg_legs の、その機体の最新の便（昨日・今日） |
| 見る記録 | rotation_obs（前の60日） | reg_legs の「同じ日にこの便のあと同じ機体が飛んだ便」（前の60日） |
| 数え方 | 同じ曜日は2倍。いちばん多い便 | 同じ曜日は2倍。いちばん多い便 |
| 絞り方 | 今日の便で、出発の空港が合い、前の便の到着の20分以上あと | 3回以上・4割以上のときだけ。同じ便に戻ったら止める |
| 何便先 | 4 | 4 |

- 1つ目で答えが出れば2つ目は呼ばない。時刻表のない会社・見張っていない便は2つ目。
- 弱いところ：古い日も新しい日も同じ重さ（ダイヤが変わるとしばらく外れる）、機体の型を見ない、その機体自身のくせを見ない、特別塗装機の予定の便を使わない、日をまたぐ予想はしない。

## 2. 案：学ぶ予想（`supabase/migrations/20261105000152_rotation_predict.sql`）

毎晩（日本時間 4:55、pg_cron `rot-learn`）reg_legs から「機体のつながり」`rot_pairs` を作り、次の順で1便ずつ決めます。

1. **特別塗装機の予定の便**（livery_plans）：その機体の塗装名と合い、出発の空港・時刻が合えば先に。
2. **学ぶ**（前の42日）：新しい日ほど重く（14日で半分）、同じ曜日2倍、**その機体自身のつながりは3倍**。さらに
   - その便に**いつも入る機体の型**に、この機体の型が2割以上あるか
   - JAL・ANA は**時刻表**でその日に飛ぶ便か・出発の空港が合うか
   - 前の便の到着の空港・時刻より後か
   を満たす便のうち、2回以上・3割以上のときだけ出す。
3. **記録が少ないときは今の仕組みに戻す**（predict_rotation_reg と同じ決め方）。

- 予想は表に残さず関数で出す（実績とまざらない）。画面向けは `predict_rotation_v2(登録記号)`：返す形は今と同じで、`estimate: true`（「予想」と出す）と便ごとの出どころ `src`（livery／learn／base）を足した。**まだ画面にはつないでいない。**
- 毎晩、前の日を「前の日の夜の時点の記録だけで予想した」として採点し、`rot_eval` に残す（今の仕組みと案の両方）。反映後は SQL を貼らなくても当たり具合を見られる。
- 新しい表は2つとも RLS 有効・利用者からは読めない。reg_legs・rotation_obs・flight_history は読むだけで消さない。
- テスト `tests/sql/t90_rotation_predict.mjs`（28項目）を足した。既存のものも含め、SQL のテスト93本がすべて通った（模擬のデータベース）。

## 3. 比べ方（`docs/pm/rotation-backtest.sql`、読むだけ）

測る日ごとに、その日の機体の便を1つずつ「いまの便」とみなし、**前の日までの記録だけ**で4便先まで予想して、その日の実際の便と比べます。

- 方式：`base`＝今の全機の予想、`learn`＝案、`obs`＝今の JAL・ANA の予想（rotation_obs と便の実績で。数え方の単位がちがうので当たり率で比べる）
- 区分：全体／会社（呼び出し符号の頭3文字）／機種／羽田発着／出どころ（案が特別塗装・学ぶ・今の仕組みのどれで出したか）
- 列：基準の数・予想を出した数・当たり・当たり率・出したうちの当たり率
- 模擬のデータで、この SQL と毎晩の採点（rot_eval）がまったく同じ数になることをテストで確かめている。

## 4. 流してほしい SQL と貼り返し方

1. Supabase の SQL Editor に `docs/pm/rotation-backtest.sql` をまるごと貼って「Run」（表も関数も作らず、書き込みもしません）。
2. 初めは先頭の `p` のまま（前の7日）。重いときは `d_from` を `- 3` に、または `max_per_day` を `500` に。
3. 結果の表を「Copy as CSV」か全部選んでコピーして、そのまま貼り返してください。会社・機種は20件以上の区分だけ出ます。
4. 判断の目安：`learn` の1便先の当たり率が `base` より上がり、出したうちの当たり率が下がっていなければ、案を進める価値あり。

## 6. 外部データの使い方（利用規約）

- adsb.lol（ODbL 1.0）：reg_legs から作った `rot_pairs` は ODbL の「派生したデータベース」。そらメモの中で予想を出すのに使い、出典はすでに画面に書いている。データベースそのものを外へ出すときは ODbL で出す必要がある。本番で使っている旨の作者への連絡は、確認表のとおりまだ残っている。
- ODPT（時刻表・特別塗装機の予定）：予想を出すときに絞り込みに見るだけで、`rot_pairs` にはまぜない（ODbL で出す義務と、ODPT の再配布の禁止がぶつからないように）。予想を画面に出すのは成果物としての利用で、基本ライセンスの範囲。
