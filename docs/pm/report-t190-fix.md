# t190（羽田の3D を自由に動かす）が落ちる件の直し（checkin/t190-fix）

PM の依頼（11/26 0時40分）：t190 が main でも落ちる（`[data-a3-other]` を待って 30 秒で切れる／「375x667 飛ぶ：右のボタンで向きが変わる」が落ちる回もある）。

## 結論：テストの作りの問題（アプリの不具合ではない）
- **「ほかを追う」が出ない**：3D は20秒ごとに機体を読み直す（A3_POLL）。テストは画面の中の機体の記録から JL318（a1）を消すだけで、偽のサーバーは a1 を返し続けていた。重くて「消えた」判定（1.5秒届かない）の前に読み直しが来ると a1 が戻り、いつまでも「追う」のまま → `[data-a3-other]` が出ない。本物ではサーバーからも届かなくなるので、アプリは正しく動く。負荷をかけた4本同時の流しで、PM と同じ形（30秒待っても view が plane）を再現した
- **「右のボタンで向きが変わる」**：向きはこまごとに進む（1こま最大 0.1 秒ぶん）。テストは 0.8 秒だけ押して離していたので、重くてこまが少ないと 0.2 に届かない。同じ作りの「8km より遠くに行かない」（0.5 秒）なども同じおそれ

## 直したこと（tests/e2e/t190.py だけ。src/index.html・web/・3D の見た目は変えていない）
- 偽のサーバーに外す機体の組 DROP を足し、「機体が消えた」の確かめでは a1 をサーバーからも外す（開くたびに空に戻す）
- 決まった時間の待ちを「条件がそろうまで待つ」に替えた（until・hold）：消えた後の一言、つまみで前へ、上限 1,000m の札、15m で止まる、右のボタンで向き、8km の端。確かめる中身と数の基準は変えていない

## 確かめた結果
- 直す前：t190 単独は成功。CPU の負荷2つ＋4本同時の流しでは、直した途中の版（待ちだけ替えた版）でも1本が PM と同じ形で落ちた → 原因は読み直しと分かった
- 直した後：CPU の負荷2つ＋4本同時で 4/4 成功。t142 → t190 の順（run_all）で 2/2 成功。単独も成功
