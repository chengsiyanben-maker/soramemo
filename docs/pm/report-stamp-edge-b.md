## 作ったもの
1. **位置が足りないときのカード（ウェブでも）**：半券（判定できないボタン）の代わりに出す。デモ中・ログインしていないときは出さない
   - 大まかな位置しか届かない（誤差 1km 超＝iOS の「正確な位置情報」が OFF など）：「空港の判定に『正確な位置情報』が必要です」＋いまの誤差＋直し方（アプリは 設定 › アプリ › そらメモ › 位置情報、iPhone の Safari は 設定 › アプリ › Safari › 位置情報 →「正確な位置情報」をオン）。ボタンは「もう一度位置を確かめる」（取り直すだけで判定しない）と、アプリだけ「設定を開く」。良い位置が届くか、設定から戻って取り直せたら半券に戻る。判定できない位置はサーバーへ送らない
   - 位置の許可がない（ウェブ）：「位置が使えないので、チェックインできません」＋直し方（iPhone は Safari の位置情報、ほかはアドレス欄のマーク）＋「デモで試す」。アプリの I1c は今のまま
   - カードは高い精度で取った位置（印を押すときの getPos）だけで出す。ホームの静かな見張り（精度を下げて取る）では出さない（押せば取れるかもしれない人の半券を隠さないため）
2. **送信待ちの見せ方**：電波が届かず端末に保存した印は、地図のピン・図鑑・数にその場で入り、開き直しても（読み直しても）仮の印として残る（qMerge）。ホームのシート（半券のすぐ下）と図鑑の詳しい所に「羽田空港の送信待ち（14:22 記録）」の小さな札。押すと送り直す。いくつ溜まっても時刻の順に送る（今の保留の仕組みのまま）。お知らせ欄の帯にも「記録した時刻の順に送ります」を1行
3. **確定の札**：保存していた印が送れたら「羽田空港の印が確定しました」（2件以上は「羽田空港など3件の印が確定しました」）。design/micro の 05 の札・2秒。図鑑を開いていれば札を消して開き直す
4. **文の言い方をそろえた**（エラーの番号や英語は出さない）
   - 送れず保存：「通信が混み合っているため、いまの記録を端末に保存しました。つながり次第送ります。」（端末がオフラインと分かるときは「電波が届かないため、…」）。札は長い文なので 3.5 秒
   - 位置がずれている（誤差が大きい・10秒取れない・サーバーの low_accuracy）：「建物の中のため、現在地が少しずれているようです。」＋「窓の近くか屋外で、もう一度押してください。」
   - 範囲の外：「いちばん近い羽田空港まであと 2.4 km です。空港に入るとチェックインできます。」（誤差 300m 超なら「建物の中のため…」を先に添える。サーバーの out_of_range も端末でこの文に）
   - 同じ空港にもう一度：「本日のチェックインは完了しています。続けて今日の便を記録できます。」
   - 端末の時計のずれ：サーバーが「いま取った位置が古い／先の時刻」（stale_position・保留でない）と言ったとき「端末の日時がずれているようです。設定で『自動設定』をオンにしてください。」
- 入れていないもの：位置が取れない・範囲の外なのに「羽田空港として保存する」で通す案。「もう一度位置を確かめる」（範囲の外の調べ直し）は今のまま

## 本人（PM）に決めてほしいこと
1. **「正確な位置情報」が OFF のとき、カードが出るまで10秒かかる**：位置の取り方（誤差 300m 超は10秒待つ）を変えない指示のため。3秒たって誤差 1km 超ならすぐカードにしてよいか（位置の取り方の変更なので OK が要る）
2. 「本日のチェックインは完了しています」：今の決まりは「同じ空港は30分あける」なので、30分たてば同じ日でももう一度押せる。文を「さきほどチェックインしました。続けて今日の便を記録できます。」にするか、このままか
3. 大まかな位置の線を「誤差 1km 超」（判定できない線 RULE.maxAccuracy と同じ）にした。屋内で 1km を超える人にも同じカードが出る（文は「大まかな位置しか届いていない」）
4. iPhone の Safari の直し方は「設定 › アプリ › Safari › 位置情報」にした（指示の「そらメモ（または Safari）」をウェブとアプリで分けた）
5. 375×667 では許可なしのカードが長く、シートを引き上げないと下が切れる。文を短くするか
