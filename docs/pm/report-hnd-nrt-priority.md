   - 直し：記録の処理（30秒ごと）だけ、成田の学習（arr_watch・rwy_samples）に使う機体を羽田と同じ60海里までに広げた（LEARN_NM）。画面に出す成田の機体は今までどおり40海里（運用タブの見た目は変わらない）
   - adsb.lol に問い合わせる回数は**変わらない**（成田は東の円の中なので、取った答えから使う範囲を広げただけ）

   | | 前 | 後 |

2. **羽田・成田の TAF を残す**（移行198 `20261125000198_hnd_nrt_taf.sql`・_shared/taf.ts・wx-archive）
   - 表 wx_taf（原文。発表ごと・訂正も別の行）と wx_taf_hours（毎時の風向・風速・突風・視程・TEMPO/PROB の風・**その風から推定した運用 est_mode**）。RLS は ON・方針なし（利用者は読めない・書けない。書くのは関数だけ）。ずっと残す（1日300行前後・1年で十数MB）
   - est_mode は画面と同じ推定（ops_core.js。羽田は追い風7kt・都心ルートの時間・深夜も時刻で）
   - wx-archive：毎時7分の今の回で TAF も取る。新しい毎時41分の回（cron `wx-hnd-nrt`・statement_timeout 30秒）で TAF・METAR（直近6時間）を取り直し、過去の TAF を1回1日ぶん 10/15（ops_log の始まり）までさかのぼる（約41時間で終わる）
   - 過去の TAF は aviationweather.gov の date の指定で取れることを確かめた（11/1・11/18・11/24 で返った）。SPECI も METAR と同じ口で返る
   - **規約**：aviationweather.gov は米国政府（NOAA/NWS の航空気象センター）のデータでパブリックドメイン。Data API の案内（https://aviationweather.gov/data/api/）は「1分に100回まで・User-Agent を付ける」。今の使い方（1時間に最大20回ほど・User-Agent つき）はその範囲
   - 影響：チェックイン・経営のどちらにもない（表を足して、裏の関数が書き足すだけ）

3. **当たり具合を測る SQL**（docs/pm/hnd-nrt-priority-check.sql・読むだけ・7つ）
   - 1 たまり具合／2 実況の風から当てる（時間帯別：深夜・朝・南風の午後 15〜19時・そのほか）／3 風の強さ別／4 切り替わりの前後（変わってから何分・次に変わるまで何分）／5 羽田の追い風の上限と粘り（34滑走路への追い風 1kt ごとの南風の割合を、5分前の向き別に）／6 成田の A/B の使い分け（時刻別）／7 数時間前の TAF から当てる（1〜3・4〜6・7〜12・13〜30時間前）
   - 「実況から当てる」は ops_log にすでにある推定（est_mode）と実機（obs_mode）で、今日から10/15 までさかのぼって数えられる。TAF のほうは反映して2日ほどで、さかのぼった分も比べられる
   - 本番は 90日より前の ops_log・rwy_samples をファイル置き場（cold-archive）に移すので、この SQL は直近90日まで
