空港は「鉄骨や屋根によるGPSの乱れ」「搭乗直前の機内モード」「人の密集によるパケ詰まり」が日常的に起きる場所です。
そらメモでは、「通信エラーでユーザーを足止めしない（失敗させない）」ことを最優先にし、空港判定そのものはアプリ内のオフラインデータで完結させ、サーバー同期だけを後ろに逃がす設計にします。
1. 現場で失敗させないための前提設計（オフライン判定）
日本の空港・飛行場（約100箇所）の座標・ターミナル範囲・滑走路範囲のデータは容量が非常に小さいため、アプリ内にあらかじめ同梱します。
 * 位置の判定： 端末のGPSと内蔵データだけで行うため、機内モードや完全圏外でも100%判定可能です。
 * 通信の役割： 獲得した「印」をクラウドへ同期する処理だけに使います。通信できないときは端末内の送信キューへ一時保存し、オンライン復帰時に自動送信します。
2. チェックインの状態遷移マトリクス（全7状態）
端末の位置精度と通信状態に応じて、ホーム画面のチェックイン領域を以下の7状態で遷移させます。
| 状態ID | 状態名 | 判定条件 | 次の遷移先とトリガー |
|---|---|---|---|
| S1 | 圏内・オンライン | 空港ポリゴン内 ＋ 測位誤差 150m以下 ＋ 通信あり | ボタン押下 → S5（送信処理）へ |
| S2 | 圏内・オフライン | 空港ポリゴン内 ＋ 機内モードまたは圏外 | ボタン押下 → 通信を試みず即 S6（予約保存）へ |
| S3 | GPSズレ・測位不安定 | 測位誤差 150m超、または直近30分以内に空港圏内履歴あり | 「近くにいますか？」カード表示 → 再測位で S1/S2、または確定操作で S6 へ |
| S4 | 位置情報の権限不足 | 位置情報未許可、またはiOS「正確な位置情報」がOFF | 権限案内カード表示 → 設定変更後に S1〜S3 へ |
| S5 | 送信中（タイムアウト監視） | S1でボタン押下直後（最大 3.5秒 待機） | 成功 → S7（確定）／ 3.5秒超過・エラー → 自動で S6 へ |
| S6 | 送信待ち（予約保存済み） | 端末に「空港・時刻・位置」を保存済みで未同期 | 通信復帰時（アプリ起動・復帰・電波回復）に自動送信 → S7 へ |
| S7 | チェックイン確定済み | 本日同空港の印が確定済み | 当日中は確定状態を表示。翌日以降に再訪問でリセット |
3. 例外ケース別の画面UIと文言案
すべての画面はライトグレー背景（#F2F4F7）＋白い角丸カード＋ピル型ボタン＋黒い区切り線なしで統一します。
ケースA：機内モード・圏外でのチェックイン（S2 → S6）
搭乗直前にシートベルトを締めたあとや、着陸して機内モードを解除する前に最も多く使われるフローです。

② ボタンを押した直後の完了カード
 * 上部ステータスビル： 送信待ち（背景 #E8ECF2・文字 #111827）
 * 印ビジュアル： 滑走路ライン＋HND をやや淡いトーン（不透明度65%）で表示し、未確定であることが一目でわかるようにします。
 * 見出し： 羽田空港の記録を保存しました
 * 記録時刻： 14:22（大きく太字・24px）
 * 説明文： インターネットにつながると自動で送信され、現地の印が確定します。
 * ピル型ボタン： 今日の便を記録する（搭乗便の記録もオフラインのまま端末に保存できます）
ケースB：ターミナル奥・地下でのGPSズレ（S3）
ターミナル中央部や地下駅直結フロアでは、GPS座標が一時的に数km離れた場所へ飛ぶことがあります。「空港の外にいます」と突き放さず、直前30分の位置キャッシュと空港境界から2km以内の低精度測位を拾って救済します。

 * 挙動の意図： まず「位置を更新してチェックイン」で窓際やWi-Fi測位による再取得を3秒だけ試みます。それでも屋内遮蔽で座標が戻らない場合は、下の副ピルから「予約保存」として通すことで、ユーザーに「窓際まで歩かせる」負担をかけません。
ケースC：電波はあるがパケ詰まり・通信タイムアウト（S1 → S5 → S6）
空港は人が密集しているため、アンテナ表示が立っていても通信が詰まることが頻繁にあります。ここで「通信エラーです。やり直してください」という警告ダイアログを出すのは避けます。
 * 処理ルール： ボタン押下後の通信待機は3.5秒で打ち切り、エラー画面を出さずにそのままS6（送信待ち完了カード）へ自動移行します。
 * 完了カードの文言：
   * 見出し： 羽田空港の記録を保存しました
   * 説明文： 通信が混み合っているため、いまの記録を端末に保存しました。つながり次第自動で確定します。
 * UX上の効果： ユーザーから見ると「1タップでちゃんと記録できた」体験になり、連打や離脱がなくなります。
ケースD：位置情報権限OFF / iOS「正確な位置情報」OFF（S4）
特にiOSでは「位置情報は許可しているが『正確な位置情報』がOFF」の状態だと、数km四方の大まかな円しか取得できず空港判定ができません。

4. 「送信待ち（予約保存）」の安心感と同期仕様
端末に保存した記録が「消えないか不安」「図鑑に反映されないと寂しい」という問題を防ぐため、以下のルールで動作させます。
 * 図鑑・地図への即時反映：
   送信待ち（S6）の時点でも、ホーム地図のピンと図鑑の枠は即座に更新し、制覇数（19 / 97）もカウントアップします。図鑑の詳細画面にだけ小さく 送信待ち のピルを表示します。
 * ホーム画面での控えめなステータス表示：
   送信待ちの間、ホーム下部シートには控えめなピル 羽田空港の印を送信待ち（14:22 記録） を表示し、タップすると手動で再送信もできます。
 * 複数空港の連続予約保存（乗り継ぎ対応）：
   「羽田で機内モードのまま予約保存 → 新千歳に着陸後、機内モード解除前に新千歳でも予約保存」という操作も想定し、送信キューは複数件を時系列配列で保持し、オンライン復帰時に順番通り自動確定します。
 * 確定時の通知（邪魔にならないトースト）：
   アプリを開いている状態で通信が回復して確定したときは、画面上部に白い角丸ピルのトースト 羽田空港の印が確定しました を2秒間だけ表示して静かに消えます。
5. エラー・例外文言の書き換え基準（NG例と推奨例）
技術用語やユーザーを責める表現を排し、すべて「そらメモ」の落ち着いたトーンに揃えます。
| 発生する事象 | NG文言（不安・ストレスを与える表現） | そらメモの推奨文言 |
|---|---|---|
| 通信タイムアウト | 通信エラーが発生しました（Error 504）。電波の良い場所でやり直してください。 | 通信が混み合っているため、いまの記録を端末に保存しました。つながり次第自動で確定します。 |
| GPS精度の低下 | GPS信号が弱いため現在地を取得できません。屋外へ移動してください。 | 建物の中のため、現在地がすこしずれているようです。 |
| 空港エリア外 | 対象スポットの半径外です。チェックインできません。 | いちばん近い羽田空港まであと 2.4 km です。空港エリアに入るとチェックインできます。 |
| 同日重複タップ | 本日はすでにチェックイン済みです。 | 本日のチェックインは完了しています。続けて今日の便を記録できます。 |
| 時計の大幅なズレ | 端末の時刻設定が不正なため登録できません。 | 端末の日時設定がずれているようです。設定アプリで「自動設定」をオンにしてください。 |
