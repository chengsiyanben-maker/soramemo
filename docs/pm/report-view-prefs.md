## 作ったもの
- 移行 `20261108000157_user_view_prefs.sql`（表と RLS をセット）
  - 表 `user_view_prefs`：1人1行。`user_id`（auth.users を on delete cascade）・`prefs`（JSON の「もの」、16KB まで）・`fmt`（中身の形の版、1〜100、アプリが決める）・`suggest_shown_at`（「これを隠しますか？」を出した日時）・`rev`（直した回数）・`updated_at`
  - RLS：本人だけ読む・作る・直す・消す。ログインしていない人は何もできない。利用者が書ける列は `prefs`・`fmt` だけ（`rev`・日時はサーバーが入れる）
  - `rev`：作ると1、直すたびに＋1。別の端末と同時に直したかは `update … where user_id = 自分 and rev = 前の値` が0行かで分かる（上書きしてよければ条件なしの upsert でよい）
  - 関数 `view_prefs_claim_suggest()`：まだ提案を出していなければ true を返して日時を入れる。2回目からは false（別の端末で同時に開いても true は1回だけ）。行がなければ空の設定で作る。これでは中身と rev は変わらない
  - 消す（行の delete）＝「全部乗せに戻す」に使ってよい。ただし提案の日時も消えるので、戻すボタンは `prefs = '{}'` に update する方がよい（提案が2回出ない）
- 退会：auth.users の削除で一緒に消える（cascade）。delete-account の処理は変えず、説明の行に表を書き足しただけ
- テスト `tests/sql/t97_user_view_prefs.mjs`（38項目）

## チェックイン担当へ（使い方の案。中身の形はチェックイン担当が決める）
- 読む：`from('user_view_prefs').select('prefs, fmt, rev, suggest_shown_at').maybeSingle()`。行がない＝全部乗せ
- 保存：`upsert({ user_id, prefs, fmt })`。中身の例：`{"off": {...}, "tabs": [...], "aps": [...]}`（いまの LAYOUT とほぼ同じ形）
- 提案：アンケートに答えたあと `rpc('view_prefs_claim_suggest')` が true のときだけ出す
- 「今ひな形を使っている人の表示は変わらない」：サーバーに行がなく、端末に soramemo.layout か撮影・修行のひな形があれば、いまの見え方を prefs にして1回だけ上げる（例 `{"from_persona": "spot", ...}`）。上げるかどうか・形はチェックイン担当が決める
- ログインしていないときは今のまま端末に保存
