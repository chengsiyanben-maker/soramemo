# 新規登録の画面とプロフィールのつなぎ込み：報告（チェックイン担当・2026-11-05）

ブランチ：`feat/signup`（main から作り、`data/signup-profile` を取り込み済み）。main には入れていない。本番の Supabase にも流していない。

## 作ったもの
- **全画面の登録・ログイン**（`src/index.html` の `dAuth`）。画面案 `docs/design/signup`（ブランチ design/signup）の8画面を、色・形・文言ごと本番の画面にした
  - ログイン →「はじめての方は新規登録」→ メール → コード → 表示名 → 使い方のアンケート → 同意 → 位置情報の説明 → ホーム
  - 表示名の初めの値は空。1〜20文字、`@` を含むもの（メールアドレス）は不可
  - アンケートの答え（spot・shugyo・casual・unanswered）を `user_profiles` に保存し、その場で構成（タブの並び・ホームに出すもの）を切り替える。「あとで決める」「答えずに進む」は unanswered で保存し、気軽の構成で始める
  - 同意はチェックを入れてからボタンを押す形。`agree_terms('2026-10-15', '2026-10-21')`（利用規約・プライバシーポリシーの改定日）で記録する
  - 位置情報は、この画面のボタンを押してから端末の確認を出す
  - ホームに、登録直後だけの「ようこそ」カード（表示名と、答えに合わせた最初の一歩）。× で閉じる
- **登録済みのメールで新規登録** → コードを確かめたところで「このメールアドレスは登録済みです」を出し、新しく作らずに今のアカウントでログインして続ける（表示名・答えは書き換えない）
- **登録していないメールでログイン** → 「まだ登録されていません」→「新規登録へ進む」（メールを入れたまま）。ログインからはアカウントを作らない（`shouldCreateUser:false`）。ホームのログイン欄も同じ
- **今いる利用者**（同意が空）→ 次に開いたとき・ログインしたときに、同意の画面を一度だけ出す。Esc では閉じない。規約の版が変わったときも出す
- **同意しない人** →「同意しないでログアウト」でログアウトし、ログインの画面へ。同意の記録は作らない
- **構成の答えの移し替え**：端末の localStorage に答えがあり、サーバーが未回答なら `user_profiles` に移す。サーバーに答えがあれば、その構成に合わせる（ほかの端末でも同じ構成）。マイページで構成を変えるとサーバーの答えも変わる
- **マイページ**：名前は表示名（なければ今までどおりメールの@より前）。「表示名 ― 変える」の行を足した（登録と同じ画面で直す）。アカウント削除は今ある入口のまま
- ログイン画面の「デモで試す」、ホームのログイン欄の「はじめての方は新規登録」「登録しないでデモで試す」
- ロボット除け（Turnstile）は登録の画面にも置いた（送り直しのため、コードの画面にも）
- プロフィールの表が読めないサーバー（移行前）では、画面で止めずにこれまでどおり使える

## 画面案と違えたところ
1. **コードの箱の数**：画面案は6けた固定。今のログインに合わせて6〜10けたを受け付け、入れた数に合わせて箱が増える。`config.js` に `otpLength` を書けば、その数に固定して全部入れたら自動で確かめる（書かなければボタンで確かめる）
2. **ログイン画面の右上に「あとで」**：登録もデモもせずにホームを見たい人のため（今のアプリはログインしなくても見られる）
3. **同意の画面に「同意しないでログアウト」**：同意しない人の出口として足した。チェックを入れるまでボタンは薄く押せない（画面案どおり）
4. **表示名・位置情報の画面に戻るボタンを置かない**：表示名はコードを確かめたあと、位置情報は同意を記録したあとなので戻らない（表示名の画面から前のコードに戻っても意味がないため）
5. **アンケートの絵**：絵文字をやめて線の絵にした（画面案のメモどおり）
6. **文言**：アンケートの補足は「下のタブの並びとホームに出すものを変えます」に、同意の3つ目は今のマイページの言葉「アカウントを削除」に、位置情報の1つ目は今のホームの「半券を切って」に合わせた
7. **ホーム**：画面案の地図とシートの絵はそのままにせず、今のホームに「ようこそ」カードを1枚足しただけ
8. **暗い表示**：今のアプリが明るい表示だけなので、登録の画面も明るい表示だけにした
9. **はじめて開いた人**：今ある使い方の案内（3枚）のあとに、ログインの画面を出す

## 本人に決めてほしいこと
1. ~~コードのけた数~~：6けたに決まった（11/5。下の追記）
2. **ログインからアカウントを作らないこと**：ログインの欄で知らないメールを入れると「まだ登録されていません」と出る（＝そのメールが未登録だと分かる。Supabase の仕組み上、今も送り方で分かる）。よければこのまま
3. **登録済みかどうかを、コードを送る前に知らせるか**：今は「コードを確かめたあと」に知らせる。送る前に知らせるには、メールの有無を答えるサーバーの関数が要り、登録の有無を調べられてしまう危険もあるので、作っていない
4. **規約の改定で同意を取り直すこと**：版（改定日）が変わったら同意の画面を出すようにした。アプリの `TERMS_VER`・`PRIVACY_VER` を変えた日から出る
5. **同意しないで登録をやめた人のアカウント**：サーバーには空のアカウントが残る（次にログインすると表示名から続く）。消すかどうか
6. 反映（「反映して」）のときは、データ担当の移行（`20261104000146_user_profiles.sql`）を先に流す。番号は `node tools/migrations.mjs rebase` で付け直す
