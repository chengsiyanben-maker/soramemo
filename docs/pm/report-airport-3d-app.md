# 報告：空港の3D（アプリ・1回目）

ブランチ checkin/airport-3d（main 61ba9c7 から）・下書きのプルリクエスト。本番には入れていない。
指示：PM 11/17 18時05分の3つめ・決定事項【11/17】「空港の3D はおすすめで作る（design/airport-3d の最後の版）」。

## 作ったもの
- 入口（羽田の空港ページだけ）
  - 数字のカードの下に小さな「3Dで見る ›」のピル（押すと直接開く・横に「押すと読み込みます（約0.2MB）」）。844・667 で開いてすぐ見える
  - 「空港の今」のカードの見出しのすぐ下に止まった見本の絵（滑走路の端から描いた SVG。何も読まない）と「3Dで見る ›」
- 3D（全画面）：押したときだけ three.js（jsdelivr の 0.160.0・圧縮で約170KB）を読む。読み込み中は「やめる」、読めないときは「もう一度」
  - 上：閉じる・題「羽田 3D／機体の位置は約1分遅れ」・… （軽い表示・データの出典）。視点のピル 全体／管制塔／機体
  - 全体は北の上空から南へ見る（4版）。指で左右に回せる。空の機体は見つけやすいよう大きく描く。影と地面までの点線
  - 管制塔は約116m から、はじめは南（C 滑走路と進入の向き）。機体は選んだ機体のうしろから（ピルが便名になる）。機体のピルを先に押すと「見たい機体を押してください」と ×
  - 名札は空の機体だけ・高さつき（「JL 318 600m」）。重なる名札は近い機体を先に。シートと上の段には重ねない
  - 下のシート：「羽田の近くの機体 ○機」・便名・どこから／どこへ（空港の今の便の一覧から）・着陸まで約○分＋○ 滑走路へ／離陸中／上昇中・特別塗装機の札
  - 押すとカード：便名・福岡 → 羽田・特別塗装機の札と塗装名・機種・登録記号・高さ・着陸まで・「この機体から見る」「機体図鑑 ›」・注意の1行
  - 約1分遅れ：airport-traffic を20秒ごとに読み、1分前の時刻を2つの答えの間でつなぐ（ない所は速さと向きで先を読む）。届かなくなった機体は止めずに消す
  - 空：日の出入り（端末で計算）で昼・夕方・夜。夜は滑走路の灯り（白）とターミナルの窓（琥珀）。見通し5km 未満は霧を濃く、札「霧（○時の通報）」「雲が低い（○時の通報）」。天気は印・実績にしない
  - 特別塗装機の尾翼は昼だけ金（夜は灰）
  - 電池20%以下（充電していない）で軽い表示に自動（機体は印・灯りなし・20秒ごとに描く・名札なし）。「ふつうに」で戻す
  - 出典：右下に「adsb.lol（ODbL）・AIP JAPAN ⓘ」、5秒で「出典 ⓘ」に畳む。押すとシート「航法には使えません。形は簡単にしています。」と出典の一覧
  - デモ（サーバーなし）でも空港の形は出し、「デモでは機体の位置は出ません」
- 夜の画面（data-night="on"）の色：白い縁のピル・金を使わない

## まだのもの（データ担当の依頼待ち）
- 空港の形は仮：滑走路の端（HND_RWY・AIP JAPAN）とターミナルの位置から作った島とターミナルの箱。OSM・PLATEAU の形のファイルが来たら差し替える（出典の文も「© OpenStreetMap・PLATEAU」に）
- 地上の機体：今の airport-traffic は地上の機体を返さないので、一覧は空の機体だけ（「地上の機体はまだ出ません」と書いた）。?view=3d が来たら切り替える
- 機体の大きさは機種ごとのおおよその長さ（約40機種）。FAA の表が来たら置き換える
- 管制塔の位置はおおよそ（高さ 115.7m は調べのとおり）

## 本人に決めてほしいこと
1. 入口の字「押すと読み込みます（約0.2MB）」：画面案の 約1.5MB は見本で、実際は three.js の約0.2MB（形のファイルが来たら少し増える）
2. 全体の視点は縦長の画面だと 30km の円が入りきらない。今は空港の先（南）の機体が入る距離にし、指で回して見る形。もっと引くと空港が小さくなる
3. 写真の中で、カードを開いたところ（04）の空の上の方が平らな水色に写る。ヘッドレスの撮影のときだけかもしれない。iPhone で見てほしい
