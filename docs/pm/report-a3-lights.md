# 報告：滑走路の灯りと機体をもっと現実的に（checkin/a3-lights）

PM 11/21 21時35分の指示（本人「滑走路のライトをもっとリアルに、機体も現実的なものにしたい」）。main 3665d4c（#171）から作った。本番にはまだ出していない（本人が写真を見て OK してから）。

## 作ったもの
### 灯り（夕方と夜だけ。昼は出さない）
- AIP JAPAN RJTT の AD 2.14 の表（滑走路の端ごとの進入灯・PAPI・接地帯・縁と中心線の間隔）を A3_LGT に持たせて並べた
  - 滑走路の縁：白、端から600m は黄（A・B は60m おき、C・D は30m おき）
  - 中心線：白、端から900〜300m は赤と白を交互、最後の300m は赤（A・B・D は30m、C は15m おき）
  - 末端の緑（ずらした末端 16R・16L・34R はその位置）・翼の形の緑の列（04・05 はなし）・終わりの赤
  - 接地帯の白（900m。進入灯のある6か所）
  - 進入灯 PALS：16L・34R・16R・34L・22 は900m、23 は870m、04・05 はなし。中心の列（5灯ずつ30m おき）・150m と300m の横の列・34R（CAT III）は横の赤い列。**順に流れる閃光**（遠い方から末端へ1秒に2回）
  - PAPI：4灯（34R だけ右、ほかは左、05 はなし。末端からの距離も表どおり）。**見ている所から見上げる角度で赤と白が変わる**（3°なら赤2白2）。全体の視点では上からなので白4
  - 誘導路：縁の青（90m おき）・中心線の緑（30m おき）
- 光は芯＋にじむ輪で描き、重なると足し合わせて明るくなる。夕方は控えめ（明るさ0.6・輪を小さく）
- 前の版は灯りが地面にめり込んで、管制塔や機体の視点ではほとんど見えていなかった。灯りを見ている所へ少し寄せて描く形で直した
### 機体
- 胴を回転体に（丸く尖る機首・細くなりながら上がる尾）
- 機種の形を増やした：787（大きく反る翼の先）・777（長い胴と大きな発動機・主脚6輪）・A350（上へ曲がる翼の先）・767・747・A380・737・A320・**E170/E190**（翼の下の2発）・CRJ（後ろの2発と T 字の尾翼）・**Q400・ATR**（高い翼・プロペラの羽根6枚・T 字の尾翼）
- 主脚の車輪の数（2・4・6）、発動機の後ろの排気の先。地上の機体は車輪が地面に着く高さに（前は少しめり込んでいた）
- 色は白い胴と灰色、窓の帯だけ（会社の色・ロゴなし）
- 機体の灯り（夕方と夜）：左翼の赤・右翼の緑・尾の白・衝突防止灯（胴の上と下の赤い点滅）・翼の先の白い閃光（2回ずつ）。**着陸灯**は空で脚を出しているあいだ（着陸の手前・離陸の直後）だけ
### 重さ
- 灯りと機体はアプリの中で作るので、押したときに読む量は今と同じ約0.6MB（three.js 約166KB＋羽田の形 約0.41MB）。アプリ本体が圧縮で約2.4KB 増えるだけ
- 古い端末（iPhone SE・8 まで、または CPU 4つ以下）では、はじめから影なし・機体の丸を粗く・細かい灯り（接地帯・誘導路の中心線）を出さない。重いときに自動で質を下げると、いちばん軽い質で細かい灯りを隠す
- 出典のシートに「滑走路・進入灯・PAPI の灯り：AIP JAPAN（AD 2.14）の種類と長さをもとに作成（並びと間隔はおおよそ）」を足した

## 本人に決めてほしいこと
1. 比べ写真を見て入れてよいか（灯りの明るさ・夕方の控えめさ・誘導路の青の量）
2. 灯りの表は第三者が写した AIP（nagodede.github.io の RJTT。AD 2.14 のページは 2022年10月発効）から読んだ。公式の AIS JAPAN（登録が要る）で確かめるか、このままでよいか。進入灯の閃光（SFL）は表に欄がなく、日本の PALS にふつう付くものとして描いた
3. 縁の灯りの黄（端から600m）は向きで色が変わる灯りだが、どちらの向きから見ても両端を黄にしている（簡単にした）。そのままでよいか
4. 本人の iPhone で重くないか（灯りは約9千点。重ければ細かい灯りを先に減らす）
