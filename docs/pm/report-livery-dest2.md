# 報告：行き先を便名で決めるのを本筋に（data/livery-dest2・データ担当・11/21）

PM の指示（11/21 15時50分）の続き。11/21 は土曜で定期の回として呼ばれたが、PM の積んだ指示があったのでこちらをした。

## 作ったもの
- **_shared/flight_dest.ts（新しい1か所の判定）**：呼び出し符号 → 便名 → 行き先
  1. 時刻表（flight_schedule。ODPT の JAL・ANA の国内線と国際線）で、いま飛んでいる便の到着の空港。日付でなく「出発の定刻が20時間前〜1時間後」の幅で引き、「出発〜到着の定刻＋6時間」にいまが入る便のうち到着の定刻が近いものを選ぶ（深夜便・日をまたぐ遅れ・長い国際線も見つかる）
  2. 時刻表にない便（海外の会社・エア・ドゥ・スカイマークなど ODPT にない会社）は、全機の記録から作った「いつもの時刻」（foreign_usual）の到着の空港。ふだんの到着がいまの前後2時間のものだけ
  3. どちらにもなければ今までどおり形の判定（滑走路の向き・最終進入・距離）。それでも決まらなければ知らせない
  - 問い合わせは1回の処理で時刻表1回・いつもの時刻1回（50件ずつ）に束ねる。答えは入れ物の記憶に10分（分からなかった便も）。どちらも1.5秒で打ち切り、失敗したらその回は形の判定だけ（記憶に入れない）
- **便名が分かる機体はいつも先に使う**（前の #165 は「候補が2つ以上か最終進入の外」のときだけ引いていた）
  - 運用タブの着陸・離陸の一覧（airport-traffic の build）：着陸は行き先がこの空港なら着陸（形で外れていても戻す）、ほかの空港なら外す。例外として、この空港の最終進入の12km以内・3,000ft以下ならダイバートとして着陸のまま。離陸は時刻表の出発地で決める
  - 撮影の知らせ（notifySpot）：運用タブの答えを使うので同じ判定になる
  - 特別塗装機の知らせ（nearAirports）：便名の行き先を必ず使う
  - 海外の塗装機の早めの知らせ（notifyInbound）：①時刻表の便の到着の空港 ②ふだん着く空港 ③経路のデータ（今までどおり）
- **呼び出し符号の対応に会社を足した**（flight_watch.ts の PREFIX と表 airline_codes を同じ中身に）：トキエア TOK→BV・天草 AHX→MZ・エアロK・エアプレミア・グレーターベイ・マカオ航空・四川・深圳・アラスカ・アエロメヒコ・貨物（FedEx・UPS・カーゴルックス・アトラスなど）ほか計34社。グループの別会社の便は親の便名でも引く（JAC3711 → 3X3711・JL3711、JTA603 → NU603・JL603）
- **移行192 airline_codes_more**（行を足すだけ。表の形・RLS は移行171 のまま）・テスト t131

影響：チェックイン（運用タブの一覧と知らせの行き先。画面の形・返す形は同じ）。経営は使わない。本人の記録は入っていない。

## 残る弱いところ
- 時刻表は JAL・ANA だけ。エア・ドゥ・スカイマーク・海外の会社は foreign_usual に行があるとき（前の8週に3回以上同じ時刻で飛んだ便）だけ便名で分かる。ない便は形の判定に戻る
- 便名の行き先と違う空港に降りるとき（ダイバート）は、最終進入の12km以内・3,000ft以下になるまでその空港の着陸に出ない
- Air Japan（AJX）は NH と NQ の両方の便名があるが、今は NH のまま（NQ を足すと表示の便名が変わるので、本人に聞いてから）。琉球エアーコミューター（RAC）は便名の記号が確かめられず足していない
