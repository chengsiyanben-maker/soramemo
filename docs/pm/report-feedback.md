- 確かめ方：t150（60項目）を UTC と日本時間で流す・関係する SQL のテスト（t148・t149・t147・t142・t01・t10・t12・t14・t82）・deno のテスト全部（354件）

## 作ったもの
1. **表 public.feedback**（移行211）
   - 列：id・created_at・kind（bug 不具合／request ほしい機能／airport_data 空港データの直し）・body（1〜2000字）・自動の付けたし（app_version・screen・device・last_error＝client_errors と同じ「種類」の形だけ。エラーの文は入らない）・airport（任意）・user_id（ログインしていれば）・session（起動ごとの使い捨ての値）・status（open 受付／checking 確認中／fixed 直した／wontfix 対応しない）・admin_note・updated_at
   - **位置・メール・IP の列はない**。Edge Function も IP を読まない・本文をログに出さない
   - RLS：ログインした人は自分の分だけ入れられて、自分の分だけ読める。列の権限で、本人は状態・運営のメモ・user_id を入れられず、運営のメモ・user_id・session は読めない。書き換え・消すのはだれもできない（運営の関数だけ）。自分の一覧は `my_feedback()` でも読める
   - 退会：auth.users を on delete cascade（本人の記録は消す決まり）。ログインしていない人の報告は残る
2. **送りすぎの制限**（入れる前の trigger。IP は使わない）：同じ利用者か同じ起動の値で10分に3件まで。ログインしていない人の全体で10分に30件まで（起動の値を毎回変えるいたずら避け）。断るとき 54000（入口では 429）。非常停止：`ops.flags` に `feedback_enabled = false` を入れると受け付けない（行がなければ受け付ける）
3. **ログインしていない人の入口 Edge Function feedback-submit**（ログイン案B）：決まった形だけ通し、余計なもの（位置・メールなど）は捨てる。ここから入れた行は user_id が必ず空
4. **運営の関数**（中で is_admin）：`admin_feedback_list(状態, 種類, 件数, この id より前)` → 状態ごとの数と一覧（運営のメモ・user_id・ログインの有無が見える）。`admin_feedback_set(id, 状態, メモ)` → メモは null なら今のまま・'' なら空に。admin_actions に残る
   - 運営コンソールの画面はこのリポジトリにない（本人の手元）。画面に足すのは「一覧（状態のピルで絞る）と、各行の状態の切り替え・メモ」で、呼ぶ関数は上の2つ
5. **夜の知らせ（ops-alert）に「新しい報告 ○件」**：前に届けた知らせのあとに来た報告の数を、種類ごとに載せる（本文は載せない）。止まった処理があれば今までどおりいつでも送って件数も載せる。止まった処理がなく報告だけの日は、**日本時間20時以降**の回に送る（1日1回は今までどおり）。届かなければ次の回にその分も合わせて数える

## 影響
- チェックイン・経営とも、今の画面とロジックは変わらない。表を1つ足し、ops_alert_log に列を3つ足し、ops_alert_claim を置き換えただけ（返す形は前の項目に足しただけ）
- 画面（マイページとエラーの画面の「不具合・意見を送る」）はチェックイン担当に頼む：ログインしていれば `from('feedback').insert({...})`（返す行を読まない形。読むなら列を名指し）、していなければ `functions/v1/feedback-submit` へ POST。断られたときの札は too_many（10分おいて）・closed（いまは受け付けを止めています）

## 本人に決めてほしいこと
1. 報告だけの日の知らせを **20時以降** にした。朝がよければ `ops.flags` の feedback_alert_hour を変えるだけ（例 8）。報告だけの知らせが届いた日は、そのあとに止まった処理の知らせが次の日の0時41分になる（最大3時間20分ほど遅れる）。これでよいか
2. 退会したとき、本人の報告も消す（決まりどおり）にした。直す前に消えると困るなら「user_id を空にして本文は残す」にもできる（本人の記録を残すことになるので本人の OK が要る）
3. 反映：表を足す移行なので、PM の自動の反映のあと本人に知らせる形でよいと考える（個人情報の扱いを変えるものではない。位置・メール・IP は持たない）
