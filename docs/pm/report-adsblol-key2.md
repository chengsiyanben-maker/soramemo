## 作ったもの
1. **移行190 track_quota**（表を1つ足す＋RLS）
   - `airport_tracks(p_iata, p_day)`：今日と前の7日は今までどおりだれでも（ログインなし・デモも）。それより前の日は**ログインした人だけ**、1人1時間に「空港×日」**60組まで**（同じ組の読み直しは数えない）。ログインなしは `{"error":"login_required"}`、上限は `{"error":"rate_limited","retry_after_min":n}` を返す（配列ではない）。運営（service_role など）は数えない
   - 中身は `airport_tracks_raw`（092 と同じ。直接は呼べない）に移した。airport_tracks は数える表に書くので volatile（アプリは POST なのでそのまま）。statement_timeout 8秒
   - 数える表 `track_quota`：RLS 有効・方針なし（本人も直接は読み書きできない）、`track_quota_take`（service_role だけ）からだけ書く。2時間より前の行は呼ばれたときに消す。退会で消える（auth.users の cascade）。**航跡の表と RLS は変えていない・記録は消さない**
2. **cold-tracks**（400日より前の日）：ログインの鍵（Authorization: Bearer）を getUser で確かめ、同じ上限（track_quota_take）。ログインなし 401・上限 429（Retry-After 付き）。置き場の Cache-Control を private に
3. テスト：t129（25項目）を足し、t27 の「40日前を匿名で読む」を「匿名は login_required・ログインした人は読める」に直した。deno の cold_test に1本

## 反映の順番（大事）
- 今のアプリは airport_tracks を **anon の鍵で呼んでいる**。移行190だけ先に入れると、ログインした人も8日より前の空の道すじが見られなくなる。**チェックイン担当の直しと同時に入れる**

## ほかの担当への依頼（チェックイン担当）
- `loadArt` の airport_tracks と cold-tracks の呼び出しで、ログインしているときは Authorization にログインの鍵（session の access_token）を付ける
- 返り値が配列でないとき：`login_required` は「8日より前の空の道すじはログインすると見られます」、`rate_limited` は「たくさん読んだので、○分ほどあとでまた見られます」を出す（字と出し方はデザインの原則どおり小さく。画面の字が増えるのでデザイン案は PM の判断で）
- デモと未ログインの日付の選び方は前の7日までにしてよい
