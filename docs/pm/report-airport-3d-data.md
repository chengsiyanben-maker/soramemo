## 1. 羽田の形の出どころ（外部データの確認表）
| データ | 取れるもの | 使ってよい形 | 出典の書き方 | 注意 |
|---|---|---|---|---|
| **OpenStreetMap**（ODbL 1.0） | 滑走路・誘導路・エプロン・駐機場・ターミナルの形（aeroway=runway／taxiway／apron／terminal、building）。高さ（height・building:levels）は付いている建物だけ | **よい**（商用も可）。羽田の分を切り出して低いポリゴンに直したファイルは「派生データベース」になるので、**そのファイルは ODbL で公開する**（例：リポジトリの data/3d/ に置き、ODbL と書く）。アプリのコードや画面は ODbL にしなくてよい | 3D の画面の角に「© OpenStreetMap」＋著作権のページへのリンク。形を変えているので「OpenStreetMap のデータを加工して作成」。5秒で畳んでよいが、畳んだあとも「データの出典」から見られること | OSM の財団の決まりは 3D に特別な定めはなく、一般の地図と同じ（角・読める大きさ）。羽田の分にどこまで描かれているか（誘導路・建物の高さの件数）は**今回は数えられなかった**（Overpass の読み込みの許可が取れず）。作る前に一度数える |
| **PLATEAU**（国交省の3D都市モデル） | 大田区の建物の形と高さ（ターミナル・格納庫など） | **よい**（公共データ利用規約 1.0。CC BY 4.0 と互換、ODbL でも使える。商用も可） | 「出典：国土交通省 PLATEAU（3D都市モデル・大田区）を加工して作成」。国交省が作ったように見せない | 空港の中の建物がどこまで入っているかは未確認。重いので、羽田の数棟だけを低いポリゴンに直して持つ（PLATEAU のファイルをそのまま読まない） |
| **国土地理院の基盤地図情報** | 建物の外周線（高さなし）・海岸線 | **使わない方がよい**。基本測量の成果なので、複製は承認（無償）の対象。アプリで加工して出す場合に申請が要るかは Q&A に直接の答えがなく、高さもない | 使うなら「基盤地図情報（国土地理院）を加工して作成」 | 地理院タイルを「その場で読み込む」のとは扱いが違う（今の地図は申請不要のまま） |
| **AIP JAPAN**（SWIM の AIP 閲覧） | 滑走路の端の位置・標高・長さ、誘導路の名前、飛行場の図 | **たぶんよい**。二次の資料で読んだ航空情報センターの条件：目的を問わず使ってよい、AIP は出典不要、国が作ったように見せない、運航に使われうるなら「古いかもしれない・運航に使えない」と書く。航空図に似た刊行物は水路業務法の手続きの確認が要る | 「滑走路の位置は AIP JAPAN をもとに作成。航法には使えません」（今の運用の画面と同じ） | **SWIM の原文はまだ読めていない**（ログインが要る）。今の ops_core の HND_RWY（端の緯度経度）はここからの事実なので、3D の滑走路はこれを正にし、OSM の形とずれたら HND_RWY に合わせる |
| 管制塔 | 高さ約 116m（115.7m）、日本一高い管制塔 | 事実なので使ってよい | 要らない（出すなら「国土交通省 羽田空港のページ」） | 位置の緯度経度は国交省のページになかった。OSM（man_made=tower）か AIP の飛行場の図で取る |

- TinyAirport の見た目・コード・3Dモデルはまねしない（本人の決定どおり。ライセンスの記載がない）

## 2. 機体：遅らせて出す読み方の案
今の作り（コードで確かめた）：
- 記録の処理が30秒ごとに adsb.lol から日本中の機体を取り、live_positions（便名ごとに最新の1行・位置・高さ・地上か・速さ・向き trk・機種・登録記号）を書き換えている。羽田のある東の円は毎回取る
- 見る人の airport-traffic（?iata=HND）は、live_positions の75秒以内の行を羽田のまわりの四角で読み（索引 live_positions_seen）、20秒ためて同じ答えを使い回す。記録が止まっているときだけ adsb.lol に問い合わせる
- track_points は1分に1点（百フィート単位）。なめらかに動かすには粗い

案（作るのは「反映して」のあと。表は足さない）：
| | 中身 | よいところ | 気になるところ |
|---|---|---|---|
| **A（おすすめ）** | airport-traffic に「3D 用」の読み方（例：?iata=HND&view=3d）を足す。羽田から30km・1万フィート以下か地上の機体だけ、要る項目（位置・高さ・向き・速さ・機種・登録記号・便名・見た時刻）だけ返す。**記録が止まっていても adsb.lol に問い合わせない**（止まっていたら「いまは機体が読めません」）。画面は受け取った位置を機体ごとに2〜3個ためて、**今より45〜60秒前**の位置を、前後の2つの位置の間でつないで動かす | 新しく外へ問い合わせない。30秒ごとの位置でも、遅らせるので「次の位置を予想」しないでなめらかに動く。データベースの読みは見る人の数に関係なく20秒に1回（今の羽田の地図と同じ答えを使い回せる） | 地上の機体（誘導路を走る機体）は adsb.lol の受信しだいで抜けやすい。抜けたら止めずに消す |
| B | track_points から前の30分を読んで再生する | 過去の流れを見せられる | 1分に1点で粗い。読む量が多い。3D には向かない（線を引くなら使える） |

読み取りの量の見込み（A）：
- 30km・1万フィート以下の羽田のまわりは、だいたい20〜40機の見込み（本番の数は下の SQL で確かめたい）。1機約150バイトで1回 3〜6KB（圧縮で約2KB）
- 15〜20秒に1回読むと、1人10分で約 40回・約 250KB。adsb.lol への問い合わせは増えない（記録の処理の30秒ごと3回のまま）
- 「少し遅らせる」は、なめらかに動かすためと、実際の動きよりわずかに遅いことを画面に「約1分遅れ」と書いて伝える形にする

## 3. 空：今の値で足りるか
| 要るもの | 今あるもの | 判定 |
|---|---|---|
| 雲量・雲の高さ | wx_obs.raw・metar の raw（例 FEW020 BKN040） | **足りる**（列はないので raw から読む。読む関数は画面の側で十数行） |
| 視程 | wx_obs.vis_m・metar の vis_m（9999 は vis_plus） | 足りる |
| 霧・もや・雨・雪 | wx_obs.wx（BR・FG・-SHRA・SN など）と raw | 足りる |
| 風 | wdir・wspd・wgst | 足りる（吹き流しなどに使える） |
| 気温・露点・気圧 | raw だけ | 要るなら raw から読む |
| 新しさ | 羽田（RJTT）は30分ごとの発表。metar は5分ためる・取れなければ wx_obs（3時間以内）で stale を付ける | 足りる。stale のときは「◯分前の通報」と出す |
| 日の出・日の入り・薄明 | なし | **手元で計算できる**（太陽の位置の式。誤差は1分ほど。外のデータは要らない。式を書くか、BSD ライセンスの小さな部品 SunCalc を使う） |

- 天気は空の見た目にだけ使い、印や実績にはしない（却下済みの「天気の実績・印に付く天気」に寄せない）
- METAR の出どころ（aviationweather.gov）の扱いは 11/6 の見直しで「よい」のまま。3D のために新しい問い合わせは増やさない（今の metar 関数を使う）

## 4. 機種の大きさをどこから取るか
| 出どころ | 中身 | 使ってよいか | 注意 |
|---|---|---|---|
| **FAA Aircraft Characteristics Database（おすすめ）** | ICAO の機種記号ごとの翼の幅・長さ・尾翼の高さ・進入速度など（2024年10月版、ページは2025年1月更新） | **よい見込み**。米国政府の作ったデータ（米国では著作権のない公の著作物）。ページに使い方の制限の記載なし。大きさは事実 | 出典「FAA Aircraft Characteristics Database」を「データの出典」に。ダウンロードの中身（列の名前）は今回まだ開いていない |
| メーカーの空港計画の資料（ボーイング・エアバスの Airport Planning） | 正確な寸法の図 | 数字（事実）を照らし合わせに使うだけ。図や文は写さない | 図はメーカーの著作物 |
| FAA の機種記号の一覧（JO 7340.2 の5章） | 機種記号・メーカー・型・重さの区分 | よい | 大きさの列はない |

- 要るのは羽田に来る機種だけ（だいたい30機種）。手で小さな表（機種記号・長さ・翼の幅・尾翼の高さ・形の種類＝ナローボディ／ワイドボディ／リージョナル／プロペラ）にして、アプリに持つ。表をデータベースに足すかは、作ると決まってから（足すなら移行と RLS をセットで出す）
- 形そのもの（3Dモデル）は自分で作る低いポリゴンの共通の形を、長さと翼の幅で伸ばす。外のモデルは使わない

## 5. 本人に流してほしい SQL（読むだけ・軽い）
```sql
-- (1) いま羽田のまわり（約30km の四角）にいる機体の数。live_positions は小さい表で、索引 seen_at で引く
select count(*) as all_75s,
       count(*) filter (where ground or alt_ft <= 10000) as low_or_ground,
       count(*) filter (where ground) as ground
from public.live_positions
where seen_at > now() - interval '75 seconds'
  and lat between 35.5533 - 0.27 and 35.5533 + 0.27
  and lon between 139.7811 - 0.33 and 139.7811 + 0.33;

-- (2) 前の7日に羽田に来た機種（機種の表に入れる候補）。主キーの運航日の範囲で引く
select type, count(*) as flights
from public.flight_history
where svc_date >= current_date - 7 and (dep = 'HND' or arr = 'HND') and type is not null
group by type order by flights desc limit 40;
```
(1) は時間帯で変わるので、昼と夜に1回ずつ流してもらえると読み取りの量の見込みが確かになる。
