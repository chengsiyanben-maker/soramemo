## 作ったもの（PM の6項目）
1. **選んでいる見方の分だけ読む**
   - 見方ごとに要るものを決めた（`OPS_NEED`）：滑走路＝お知らせ・特別塗装機・門限・ゴーアラウンド・機体の位置／案内板＝時刻表・海外の便・お知らせ・ゴーアラウンド／1日の山＝時刻表・昨日／定時＝定時率／空の道すじ＝航跡／短冊＝時刻表／撮る人＝時刻表・特別塗装機・ゴーアラウンド・機体の位置
   - 機体の位置（airport-traffic）は滑走路と撮る人のときだけ。ほかの見方にすると止める
   - `livery_board` の4回：95機を30機ずつ4回読んでいた（同じ関数で中身は別の機体）。サーバーの時間の上限を避けるための分け方なので全部を1回にはせず、運用では「いま飛んでいる特別塗装機」（special_now に出た機体）の分だけを1回で読むようにした。全部の機体は「すべての特別塗装機」を開いたときだけ読む（今までどおり）
   - 見方を変えたときは、3分以内に読んだ結果を使う（案内板・海外の便・お知らせ・特別塗装機を取り直さない）。1分ごとの読み直しは今までどおり
   - ログインしていない人とデモでは `flight_alerts` を呼ばない（遅れ・欠航のタイルとお知らせの欄も出さない）。空港のページのお知らせは今のまま
2. **風の欄と札の食い違い**：気象通報が届くまでは風の欄を「…／読み込み中」にし、運用の札（「風から推定」）を出さない。読めなかったときは「—／気象通報なし」と札「気象通報なし（仮の表示）」（「風から推定」と言わない）
3. **見方の帯**：はじめは左端（案内板）から。選んだ見方が画面の外のときだけ見えるところまで送る。描き直しても指で送った位置を保つ
4. **中身のない丸いボタン・名前のない小さいボタン**：調べると、どちらも**閉じた折りたたみの中身**だった（丸いボタン＝滑走路の「ほかの向き」の中の「今の運用・北風・南風…」、48×19＝一番下の「この地図について・出典」の中の adsb.lol のリンク）。閉じているあいだはブラウザが字を出さないので、名前がなく押せないように見える。開けば名前があり押せることをテストで確かめた。コードは変えていない（改善担当の見回りの道具は、閉じた details の中を数えないようにするとよい）
5. **案内板の切れと押せる範囲**：長い行き先は2行まで折る（「サンフランシスコ／から」。「から」「へ」は割らない）。「到着／出発」「すべて／国内線／国際線」「原文」「くわしく」は、見た目の大きさは変えず押せる範囲だけ縦 44px（原文は 44×44）
6. **「滑走路」の描き直し**：見方を押したら先に滑走路の中身を出し、地図の描き直し（地図を合わせる・現在地）は画面が変わったあとに回した。押した処理の中は 2ms 前後
