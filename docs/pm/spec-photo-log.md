# 撮影記録（計画の E）の仕様（撮る人用担当・11/6）

計画は Project の文書「そらメモ_撮影する人の機能_計画（10-28）」の E が正。構想段階なので、本人が「反映して」と言うまでアプリに入れない。
この文書はコードを変えない。画面はデザイン担当の画面案、表はデータ担当の移行と RLS を待ってから作る。

## 1. 目的
- 撮った写真が「どの機体（登録記号・便名・機種）」だったかを、手で調べずに残せるようにする
- 写真の撮影時刻から候補を出し、本人が選ぶ（決まったこと・10-28）。自動で決めつけない
- 特別塗装機を撮ったら、図鑑（特別塗装機だけ）に「撮った」の印を付ける

## 2. 守ること
- 写真そのものと、写真の位置（EXIF の GPS）はサーバーに送らない。読むのは端末の中だけ
- サーバーに送るのは「空港（IATA）・撮影時刻（分まで）・選んだ機体」だけ
- 候補は「予想」ではなく記録からの推定。画面に「記録からの候補です。違うときは選び直してください」と出す
- 機体図鑑は特別塗装機だけのまま。撮影記録の一覧は別の場所（下の 4-4）

## 3. 流れ
1. 写真を選ぶ（1回に20枚まで。ファイルの選択 `<input type=file accept=image/* multiple>`。アップロードはしない）
2. 端末で EXIF の撮影時刻（DateTimeOriginal、あれば OffsetTimeOriginal）を読む
   - 時差の記載がなければ日本時間とみなす
   - EXIF がない写真は、ファイルの更新時刻を出して「時刻を確かめてください」と本人に直してもらう
3. カメラの時計のずれ（分単位、−60〜＋60）を足す。設定は端末に覚える（localStorage。サーバーに送らない）
4. 空港を決める：運用タブで選んでいる空港を初めの値にし、本人が変えられる。
   写真に GPS があれば、端末の中だけで近い空港（14空港のうち、滑走路から3km以内）を初めの値にしてよい。位置は送らない
5. サーバーの関数 photo_candidates（下の 5-2）で、その時刻に空港の近くにいた機体を受け取り、近い順に3つ出す
   - 「ほかの機体」を押すと前後20分の一覧。どれでもなければ登録記号を手で入れる（形だけ確かめる）
6. 本人が選んだら photo_log に1行足す
7. 任意：写真に帯（登録記号・便名・機種・空港・日付）を入れた画像を端末で作り、端末に保存／共有する。
   作り直した画像は canvas から書き出すので EXIF（GPS を含む）は付かない。サーバーには送らない

## 4. 画面（デザイン担当の画面案を待つ。ここは中身だけ）
- 4-1 入口：運用タブの「撮る人」の見方の中に「撮った写真から記録する」。ホームの撮影カードにも小さな入口を置くかは画面案で決める（ホームの枠はチェックイン担当）
- 4-2 候補を選ぶ画面：写真の縮小（端末の中だけ）・補正後の撮影時刻・候補3つ（登録記号・便名・機種・着陸／離陸・空港にいちばん近かった時刻との差）。
  撮る人の決めごと（入れ子のカードと黒い札はやめる・フライトストリップの帯の色＝着陸は紺、離陸は薄い紺）に合わせる
- 4-3 時計のずれの設定：分の増減のピル。「写真の時刻＋ずれ＝本当の時刻」の見本を1行
- 4-4 撮った機体の一覧：計画では「記録タブの『撮った機体』」だが、今のタブ帯に「記録」タブはない（ホーム・図鑑・フライト・運用・修行・成績）。置き場所は本人に決めてもらう（下の 8）
- 4-5 図鑑：特別塗装機の札に「撮った」の印（「見た」の印 my_livery_seen と並べる）

## 5. データ（データ担当への依頼。下の 9 に依頼文）
### 5-1 表 photo_log（新規）
| 列 | 型 | 中身 |
|---|---|---|
| id | bigint（自動） | |
| user_id | uuid not null | auth.users を on delete cascade で参照（退会で消える。決定事項の「退会したら本人の記録を消す」と合う） |
| taken_at | timestamptz not null | 補正後の撮影時刻（分に丸める） |
| iata | text not null | `^[A-Z]{3}$` |
| reg | text not null | `^[A-Z0-9-]{2,10}$` |
| callsign | text | `^[A-Z]{3}[0-9]{1,4}[A-Z]?$`、不明なら null |
| type | text | 8文字まで |
| phase | text | 'arr' / 'dep' / null |
| src | text not null | 'cand'（候補から選んだ）/ 'manual'（手で入れた） |
| created_at | timestamptz not null default now() | |
- 同じ人・同じ機体・同じ分は1行（unique (user_id, reg, taken_at)）。連写を何度も入れても増えない
- RLS：本人だけ読む・足す・消す（auth.uid() = user_id）。書き換えは「選び直し」を消して足す形にするので update は許さない
- 1人1日200行まで（関数か制約で）。taken_at は「今より先」と「2000年より前」を断る

### 5-2 関数 photo_candidates(p_iata text, p_at timestamptz) returns jsonb（新規・authenticated だけ）
- 返すもの：[{reg, callsign, type, phase, at, dmin}] を、空港にいちばん近かった時刻 at と p_at の差の小さい順に20件まで
- 元：
  - 36時間より前：airport_tracks_all（空港・日・便名・空港にいちばん近い時刻・dep_here）＋ reg_legs（便名と日から登録記号と機種）
  - 36時間以内：airport_tracks_all はまだ作られていない（毎晩の rwy-learn が作る）ので、track_points（36時間で消える）と reg_legs から同じ形を作る
- 前後20分より離れたものは返さない。31日より前は断る（30日を過ぎた日は cold_done で表から外へ移されるため）
- 返すのは今も運用タブで見えている程度のもの（便名・登録記号・機種・時刻）。航跡の点は返さない
- 対象は記録している14空港だけ（airport-traffic の RECORD と同じ）。それ以外の空港は「この空港は記録がないため候補を出せません。登録記号を入れてください」

### 5-3 図鑑の「撮った」
- 新しい関数は作らず、photo_log を本人が読んで、特別塗装機の一覧（LIVERY_NAMES）にある登録記号に印を付ける

## 6. 完了の条件
- 写真を選ぶと、補正後の時刻と候補3つが出て、選ぶと photo_log に1行入る（デモの始め方でも動く。デモは端末の中だけに残す）
- 写真・GPS がネットワークに出ていない（テストで送った中身を見て、画像のバイト列と緯度経度がないことを確かめる）
- EXIF がない写真・時差の記載がある写真・時計のずれ＋15分の3つで、時刻が正しく出る
- 記録のない空港・31日より前・未来の時刻で、正しい言い方が出る
- 特別塗装機を選ぶと図鑑に「撮った」が付く
- テスト：tests/e2e に新しい1本（EXIF を入れた小さな JPEG を手元で作って使う）、tests/sql に photo_log の RLS と photo_candidates の1本。t63・t113 も通る
- スマホ幅（390・375）で撮って確かめる

## 7. 気をつけること
- iPhone の写真（HEIC）は、ファイルの選択で JPEG に変わるときに撮影時刻は残るが GPS が消えることがある。実機で確かめる（GPS がなくても空港を手で選べば進める）
- EXIF を読む部品は外から入れず、JPEG の APP1 だけを読む小さな関数を書く（読むのは撮影時刻と時差と GPS だけ）
- 候補の精度は、空港にいちばん近かった時刻との差だけで並べる。撮影地からの見え方（B の計算）で並べ替えるのは次の段階

## 8. 本人に決めてほしいこと
1. 撮った機体の一覧の置き場所：「フライト」タブの中に「撮った機体」を足す／運用タブの「撮る人」の見方の中／マイページのタイル
2. 帯を入れた画像を作る機能を最初の版に入れるか（入れないと作る量が半分ほどになる）
3. 1回に選べる写真の数（20枚でよいか）

## 9. 依頼文
### 9-1 デザイン担当へ（画面案の依頼）
撮影記録（計画の E）の画面案をお願いします。中身は docs/pm/spec-photo-log.md の 3・4 です。
- 画面は4つ：入口（運用タブの「撮る人」の見方の中）・候補を選ぶ画面・時計のずれの設定・撮った機体の一覧（置き場所は本人の決定待ちなので、フライトタブの中の形で1案）
- 撮る人の決めごとに合わせてください：入れ子のカードと黒い札はやめる／着陸は紺（--hero）・離陸は薄い紺（#8C9AAE）の左の帯／時刻と便名は標識の書体（--sign）／画面全体を黒にしない
- 候補には「記録からの候補です。違うときは選び直してください」を1行。写真は送らないことを短く書く（例「写真はこの端末の中だけで使います」）
- 図鑑の特別塗装機の札に付ける「撮った」の印（今の「見た」と並ぶ形）
- 帯を入れた画像（本人の決定待ち）は、入れるとしたら帯の見本を1枚

### 9-2 データ担当へ（表と関数の依頼）
撮影記録のために、表 photo_log と関数 photo_candidates をお願いします。中身は docs/pm/spec-photo-log.md の 5 です。
- 移行と RLS をセットで。photo_log は本人だけ読む・足す・消す（update なし）、auth.users を on delete cascade で参照、unique (user_id, reg, taken_at)、1人1日200行まで
- photo_candidates は authenticated だけ。36時間より前は airport_tracks_all＋reg_legs、36時間以内は track_points＋reg_legs。前後20分・20件まで・31日より前は断る
- tests/sql に RLS（他人の行が読めない・書けない）と候補の並び順のテストを
- 本番には適用しないでください（本人の「反映して」待ち）
