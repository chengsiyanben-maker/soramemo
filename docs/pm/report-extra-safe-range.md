# 番外編の判定範囲の見直し案（データ担当・11/26 本人の OK ②）

ブランチ data/extra-safe-range（main 594dd3e から）。**移行207（案）・テスト t146**。PM が見てから出す。影響：チェックイン（番外編10か所の印を押せる範囲が少し広がる）。経営は関係しない

## 1. 考え方
- 「敷地や門に近づかず、公道や見学できる所から押せる」こと。判定は中心の点から半径 radius_m の円の中だけなので、**円が敷地の外の道まで届いていれば、門や敷地に近づく必要はない**
- そこで、敷地の端の見込み＝中心から滑走路のいちばん遠い端まで＋種類ごとの余白、を出し、今の半径が届かない所だけ広げる（**狭める所はない**＝今押せる所は押せたまま）
  - 余白：基地（自衛隊・米軍）＝端の先の柵まで 300m＋外の道 200m＝500m／民間の飛行場・滑空場＝柵まで 100m＋外の道 200m＝300m／ヘリポート＝敷地 100m＋外の道 200m＝300m（滑走路は見ない）
  - 滑走路の端：OurAirports runways.csv（パブリックドメイン・#243 で取った data/ap_shape/raw）の両端の座標。両端がなければ長さの半分（推定）、長さもなければ種類の決まり（基地 1,000m・飛行場と滑空場 300m）
  - 上限 3,000m
- 「中心点を敷地の外の見学できる所へ寄せる行を足す」形（案2）は今回は作っていない：見学できる所の座標を規約のはっきりした元から取れない（OSM は配るデータに混ぜない決まり）のと、番外編はターミナルの行を判定に使わない作り（judge.ts の locate）なので、行を足すにはチェックインの判定のコードの直しが要る。本人が見学所（例：道の駅かでな）を挙げてくれれば、その点を中心に寄せる案を作れる
- 病院のヘリポートは今の番外編にない（12か所はすべて国交省の公共用ヘリポート）。入れるときは「病院の敷地に入らない」を最初の決まりにする
